\chapter{Анализ задачи и обзор существующих решений}\label{ch:problem}

Текстовые документы хранят учебные материалы, рабочие файлы, отчёты,
инструкции, заметки и~другие сведения. Когда таких документов становится много,
ручная раскладка по~папкам начинает занимать заметное время. Поиск по~названию
или отдельным словам помогает найти известный файл, но~не~решает задачу
постоянного распределения документов по~смысловым категориям. Для этого нужна
автоматическая классификация, то~есть отнесение документа к~одной из~заранее
понятных групп~\autocite{Sebastiani2002TextCat,Manning2008IR}.

\section{Постановка проблемы}\label{sec:ch1/domain}

Документом в~данной задаче считается текстовая запись, которую можно прочитать
и~обработать программно. Это может быть короткая заметка, письмо, отчёт,
фрагмент инструкции или другой текстовый файл. Категорией называется понятная
пользователю группа документов: например, «учёба», «работа», «договоры»,
«отчёты» или «личные заметки». Категория нужна не~сама по~себе, а~для более
быстрого поиска и~порядка в~архиве.

Простейший способ организации документов "--- ручное создание папок и~перенос
файлов. Такой способ хорошо работает при~малом числе документов. Если же архив
пополняется каждый день, пользователь начинает тратить время на~однотипные
действия. Часть документов попадает не~в~ту папку, часть остаётся без категории,
а~один и~тот~же документ иногда подходит сразу под несколько признаков.

Поиск и~фильтры решают только часть проблемы. Поиск требует, чтобы пользователь
помнил слово из~документа или его название. Фильтр требует заранее заданного
правила: например, «если в~названии есть слово `отчёт', положить в~папку
`отчёты'». Но~в~тексте может не~быть точного ключевого слова, хотя по~смыслу
документ относится к~нужной теме. Также фильтры должны иметь заранее заданные
категории, по которым будет производиться сортировка, что добавляет сложность
конечному пользователю для организации своих документов. Поэтому со~временем
начали применять методы, которые учитывают не~только отдельные слова,
но~и~похожесть документов между собой.

Система, которая автоматически сортирует и предлагает дополнить имеющиеся категории
новыми, решала бы такую задачу, но для такой системы важна локальная
обработка. Многие документы содержат личные данные, учебные работы, рабочие
материалы или внутренние сведения организации. Если отправлять текст во~внешний
сервис, пользователь теряет прямой контроль над~тем, где этот текст хранится
и~как он обрабатывается. Локальное размещение уменьшает этот риск: текст
остаётся на~устройстве пользователя или внутри его инфраструктуры.

Таким образом, задача состоит не~только в~том, чтобы выбрать алгоритм
классификации. Нужно описать весь путь: подготовку текста, поиск похожих
документов, обучение по~размеченным примерам,оценку качества и~обработку
документов, которые не~подходят ни~под одну известную категорию.

\section{Обзор существующих подходов и решений}\label{sec:ch1/systems}

Подходы к~сортировке текстовых документов развивались постепенно. Сначала
использовались ручные правила и~ключевые слова. Затем стали применять
вероятностные методы, которые учатся по~готовым примерам. Позже появились
нейронные модели, способные строить числовое представление целого текста и~по
нему сравнивать документы по~смыслу~\autocite{Sebastiani2002TextCat,Kowsari2019TextSurvey}.

Ниже приведены примеры таких подходов. Каждый пример показывает отдельный
способ сортировки текста: от~простых правил до~обучения по~готовым примерам.

\textbf{Sieve} "--- язык правил для сортировки сообщений при~их доставке.
В~RFC~5228 он описывается как простой и~ограниченный язык: пользователь задаёт
проверки и~действия, а~система выполняет их по~порядку~\autocite{Guenther2008Sieve}.
Проверка может смотреть на~адрес отправителя, заголовок, размер сообщения или
наличие нужной строки. Действие указывает, что сделать дальше: оставить
сообщение, переложить его в~папку, переслать или удалить. Например, правило
может звучать так: если в~заголовке есть слово «отчёт», переложить сообщение
в~папку «отчёты». Такой подход легко объяснить пользователю, но~он плохо
понимает смысл текста. Если нужная мысль выражена другими словами, правило
может не~сработать.

\textbf{Байесовский фильтр спама} "--- способ отличать спам от~обычных
сообщений по~словам, которые встречались в~размеченных примерах. В~работе
И.~Андроутсопулоса и~соавторов такой фильтр строится на~наивном байесовском
классификаторе: сначала берутся сообщения с~готовыми метками «спам» и
«не~спам», затем для слов оценивается их связь с~каждым классом
\autocite{Androutsopoulos2000NaiveBayesSpam}. Если слово часто встречалось
в~спаме, оно получает больший вес для класса «спам». Если слово чаще
встречалось в~обычных сообщениях, оно получает больший вес для второго класса.
При проверке нового сообщения фильтр складывает влияние найденных слов
и~получает общий балл. Если этот балл выше заданной границы, сообщение
попадает в~спам. Такой метод уже учится на~примерах, но~обычно решает задачу
с~двумя классами, а~для сортировки документов часто нужно больше категорий.

\textbf{Gmail Priority Inbox} "--- способ поднять важные сообщения выше
остальных. Авторы описывают его как систему обучения, которая смотрит
на~признаки сообщения и~на~действия пользователя~\autocite{Aberdeen2010PriorityInbox}.
К~признакам относятся отправитель, получатели, слова в~сообщении и~другие
данные, доступные почтовому сервису. Действия пользователя тоже важны: какие
сообщения он открывает, на~какие отвечает, какие помечает как важные или
неважные. На~основе этих сигналов система решает, стоит ли показать сообщение
в~более заметной части списка. Такой подход снижает ручную работу, но~он
делит сообщения по~важности, а~не~по~пользовательским смысловым категориям.

\textbf{Outlook Focused Inbox} "--- встроенная сортировка сообщений на~две
вкладки: Focused и~Other. В~документации Microsoft указано, что система
помещает важные сообщения во~вкладку Focused, а~остальные показывает
во~вкладке Other~\autocite{Microsoft2024FocusedInbox}. При этом она учитывает
контакты и~действия пользователя. Если пользователь вручную переносит
сообщение между вкладками, сервис использует это действие как подсказку
для~будущей сортировки. По~смыслу это похоже на~обучение по~обратной связи:
пользователь исправляет решение, а~система старается повторить такой выбор
позже. Ограничение остаётся тем~же: сервис даёт только две группы и~работает
в~рамках готовой почтовой среды.

\textbf{TaskTracer} "--- исследовательская система, в~которой сообщения
связываются с~проектами пользователя. В~работе В.~Кейзер сравниваются
алгоритмы, которые обучаются по~мере поступления новых примеров
\autocite{Keiser2009TaskTracer}. Такой режим можно объяснить просто: сначала
пользователь показывает системе несколько сообщений для каждого проекта, затем
система относит новые сообщения к~похожим проектам, а~после исправлений
обновляет свои знания. Например, если сообщения со~словами «договор»,
«смета» и~«подпись» часто относились к~одному проекту, похожее новое сообщение
получит тот~же проект. TaskTracer ближе к~задаче классификации, но~он
рассматривает заранее известные проекты и~почтовые сообщения, а~не~общий
архив текстовых документов.

\textbf{EmFORE} "--- метод автоматического построения правил для распределения
сообщений по~папкам. Авторы предлагают обучать правила на~тех папках, которые
уже есть у~пользователя, и~обновлять эти правила, когда поток сообщений
меняется~\autocite{Singh2023EmFORE}. Правило может учитывать отправителя,
слова в~теме и~другие признаки. Например, если пользователь часто кладёт
сообщения с~одного адреса и~с~похожей темой в~папку проекта, система может
создать похожее правило сама. Плюс такого подхода в~том, что правило можно
прочитать и~понять. Минус в~том, что классы берутся из~существующих папок,
поэтому система зависит от~того, как пользователь уже организовал свой архив.

Эти примеры показывают, что готовые решения закрывают только часть задачи.
Ручные правила понятны, но~требуют постоянной поддержки. Вероятностные методы
и~обучение по~примерам лучше работают с~разными формулировками, но~зависят
от~качества разметки. Сервисы сортировки сообщений помогают в~своей среде,
однако они не~дают полноценную локальную сортировку произвольных текстовых
документов по~нескольким смысловым группам.

\section{Постановка задачи классификации}\label{sec:ch1/task}

В~общем виде задача классификации состоит в~том, чтобы разделить множество
объектов на~заранее заданные классы. При~этом для~части объектов уже известны
правильные классы: такие пары образуют обучающую выборку. По~этой выборке
нужно построить алгоритм, который сможет получить новый объект и~указать,
к~какому классу он относится.

В~данной работе объектом считается текстовый документ, а~классом "---
пользовательская категория, например «учёба», «работа», «финансы» или
«личное». Обучающая выборка состоит из~документов, которые пользователь уже
отнёс к~нужным категориям. Для документа \( x_i \in X \) известна метка \( y_i \in Y \),
поэтому пара \( (x_i, y_i) \) показывает системе один пример правильного
решения. После обучения система получает новый документ \( x \), для~которого
метка ещё не~известна, и~должна выбрать подходящую категорию. Так как мы~не
знаем класс для~нового объекта, мы считаем класс объекта случайной величиной \( y \).
Например, документ об~учёбе может классифицироваться как~«учёба»
с~вероятностью 0.95 и~как~«финансы» с~вероятностью 0.05. Таким образом, чтобы
классифицировать объект, нам нужно знать условное распределение этой случайной
величины на~этом объекте \( p(y|x) \).

Задача нахождения \( p(y|x) \) при~данном множестве меток \( Y \) и~данном наборе
размеченных примеров \( D = \{ (x_i, y_i) \} \) называется задачей классификации.

\section{Многоклассовая классификация с отказом от решения}\label{sec/multitask}

Многоклассовая классификация отличается от общего вида тем, что количество классов \( K \)
подчиняется ограничению \( K > 2 \). Если \( Y = \{1, 2, \ldots, K\} \),
где \( K > 2 \), то для~каждого документа \( x \) нужно выбрать один из~\( K \)
возможных классов. Например, документ может относиться к~категории «учёба»,
«работа», «финансы», «личное» и~так далее.

Пусть для~документа \( x \) известно условное распределение \( p(y \mid x) \).
Тогда для~каждого класса \( k \in Y \) можно рассмотреть число \( p(k \mid x) \).
Это число показывает, насколько вероятно, что документ \( x \) относится именно
к~классу \( k \). Так как один документ должен быть отнесён ровно к~одному
классу, выполняется условие
\begin{equation}
    \label{eq:equation4}
    \sum_{k=1}^{K} p(k \mid x) = 1.
\end{equation}

Если система обязана всегда выбрать некоторый класс, то естественное правило
классификации имеет вид
\begin{equation}
    \label{eq:equation5}
    a(x) = \arg\max_{k \in Y} p(k \mid x).
\end{equation}
То есть алгоритм выбирает тот класс, для~которого вероятность максимальна.

Введем понятие уверенность классификации для~документа \( x \). Оно
показывает вероятность наиболее вероятного класса.
\begin{equation}
    \label{eq:class_confidence}
    \max_{k \in Y} p(k \mid x)
\end{equation}

Однако на~практике не~всегда нужно требовать от~системы обязательного выбора
класса. Для~некоторых документов распределение \( p(y \mid x) \) может быть
неопределённым. Например, если система получила значения
\begin{equation}
    \label{eq:equation7}
    p(\text{«работа»} \mid x) = 0.51,
    \qquad
    p(\text{«финансы»} \mid x) = 0.49,
\end{equation}
то формально класс «работа» имеет наибольшую вероятность. Но разница между
двумя классами мала, поэтому такое решение нельзя считать достаточно надёжным.
В~подобной ситуации лучше не~выбирать класс автоматически, а~передать документ
пользователю для~ручной разметки.

Для~описания такой ситуации вводится специальное решение отказа. Обозначим его
через \( \bot \). Тогда алгоритм классификации принимает значения не~только
из~множества классов \( Y \), но~и~из~множества
\begin{equation}
    \label{eq:equation8}
    Y \cup \{\bot\}.
\end{equation}
Если \( a(x) = \bot \), то это означает, что система отказалась от~автоматического
решения для~документа \( x \).

Простейшее правило классификации с~отказом задаётся с~помощью порога
\( \tau \in [0,1] \). Алгоритм выбирает класс только тогда, когда максимальная
вероятность достаточно велика:
\begin{equation}
    \label{eq:decision-rule}
    a_{\tau}(x) =
    \begin{cases}
        \arg\max\limits_{k \in Y} p(k \mid x),
        & \text{если } \max\limits_{k \in Y} p(k \mid x) \geqslant \tau, \\
        \bot,
        & \text{если } \max\limits_{k \in Y} p(k \mid x) < \tau.
    \end{cases}
\end{equation}
Параметр \( \tau \) называется порогом отказа. Чем больше значение \( \tau \),
тем чаще алгоритм будет отказываться от~решения. Чем меньше значение \( \tau \),
тем больше документов будет классифицировано автоматически, но~тем выше риск
ошибочной классификации.

Это правило можно интерпретировать через вероятность ошибки. Если для~документа
\( x \) выбран класс \( k^* = \arg\max_{k \in Y} p(k \mid x) \),
то вероятность того, что выбранный класс окажется неверным, равна
\begin{equation}
    \label{eq:equation11}
    1 - p(k^* \mid x).
\end{equation}
Следовательно, отказ от~решения нужен тогда, когда эта величина слишком велика.
Например, условие
\begin{equation}
    \label{eq:equation12}
    p(k^* \mid x) \geqslant \tau
\end{equation}
эквивалентно условию
\begin{equation}
    \label{eq:equation13}
    1 - p(k^* \mid x) \leqslant 1 - \tau.
\end{equation}
То есть алгоритм принимает автоматическое решение только в~том случае, если
оценка вероятности ошибки не~превышает заданного уровня.

В~задаче пользовательской классификации документов отказ от~решения имеет
практический смысл. Если документ похож сразу на~несколько категорий или плохо
похож на~все известные категории, система не~должна обязательно выбирать одну
из~них. Вместо этого она может вернуть специальный ответ \( \bot \), после чего
пользователь сам укажет правильную категорию. Такой подход уменьшает число
ошибочных автоматических решений и~позволяет отделить надёжные классификации
от~сомнительных.

\section{Требования к данным}\label{sec:ch1/data}

Данные для классификации должны быть подготовлены так, чтобы~модель могла
увидеть связь между текстом и~категорией. Набор данных состоит из~документов
и~меток. Метка "--- это правильная категория, назначенная документу человеком.
Без таких примеров классификатор не~может научиться отличать одну категорию
от~другой.

Для работы с~нейронными сетями данные должны удовлетворять нескольким условиям.
Текст должен быть извлечён из~документа в~едином виде. Если один файл хранится
как~обычный текст, другой как~HTML, а~третий как~выгрузка из~таблицы, их нужно
привести к~общему текстовому представлению. Категории должны быть понятны
разметчику. Если категории пересекаются слишком сильно, например «работа»
и~«важное», даже человек может размечать их по-разному.

Желательно, чтобы в~каждой категории было достаточно примеров. Если категория
содержит один или два документа, модель запомнит отдельные слова, но~не~сможет
понять общий признак категории. Также полезно отделять часть размеченных
документов для проверки. Тогда модель обучается на~одной части набора, а~качество
считается на~другой части, которую модель не~видела при~обучении.

Перед обучением числовые признаки часто приводят к~единому масштабу. Для текста
это может означать нормирование вектора документа: после такой операции длина
вектора становится одинаковой для всех документов, и~при~сравнении сильнее
учитывается направление вектора, а~не~размер текста. Это важно, потому что
длинный документ не~должен получать преимущество только из-за большого числа
слов.

\section{Предобработка и нормализация текстов}\label{sec:ch1/preprocess}

Предобработка "--- это подготовка текста к~построению признаков. Она не~делает
классификацию сама, но~уменьшает шум в~данных. Шумом здесь называется всё, что
мешает выделить смысл документа: лишние пробелы, повторы, технические строки,
служебные пометки, одинаковые подписи и~случайные символы.

Обычно предобработка включает несколько шагов~\autocite{Manning2008IR}. Сначала
из~файла извлекается основной текст. Затем удаляются лишние пробелы, перевод
строк приводится к~одному виду, а~текст может переводиться в~нижний регистр.
После этого текст делится на~токены. Токеном называется отдельная часть текста,
чаще всего слово или знак. Для русского языка иногда применяют лемматизацию:
слова «документ», «документа» и~«документом» приводятся к~одной начальной форме.

Пример показывает смысл нормализации. Исходный текст:
«ОТЧЁТ!!!   По проекту. Версия 2. С уважением, Иван». После очистки он может
превратиться в~строку «отчёт проект версия». Для задачи классификации подпись
и~повторяющиеся знаки обычно несут меньше пользы, чем слова «отчёт» и~«проект».

Нормализация должна быть аккуратной. Если удалить слишком много, можно потерять
важные признаки. Например, номер договора, дата или название проекта иногда
помогают определить категорию. Поэтому правила очистки текста подбираются под
тип документов, а~не~применяются вслепую.

\section{Способы представления текста для классификации}\label{sec:ch1/repr}

Алгоритмы классификации работают с~числами, а~не~с~обычным
текстом. Поэтому документ нужно перевести в~числовое представление. Такое
представление можно понимать как~таблицу признаков: у~каждого документа есть
набор чисел, по~которым его можно сравнить с~другими документами.

Самый простой подход "--- считать слова. Документ описывается числами: сколько
раз в~нём встретилось каждое слово из~общего словаря. Такой подход называют
«мешком слов», потому что порядок слов теряется, но~частоты сохраняются.

Более полезный вариант "--- TF-IDF. Этот вес становится большим, если слово
часто встречается в~одном документе, но~редко встречается во~всём наборе
документов~\autocite{Salton1988TFIDF,Manning2008IR}:
\begin{equation}
    \label{eq:tfidf}
    w_{t,d} = \mathrm{tf}(t,d)\cdot \ln\frac{N}{n_t + 1}.
\end{equation}
Здесь \( w_{t,d} \) "--- вес слова \( t \) в~документе \( d \),
\( \mathrm{tf}(t,d) \) "--- сколько раз слово \( t \) встречается в~документе
\( d \), \( N \) "--- общее число документов в~наборе, \( n_t \) "--- число
документов, где встретилось слово \( t \), а~\( 1 \) в~знаменателе защищает
от~деления на~ноль при~расчёте для новых слов.

Пример можно задать на~пяти коротких документах: «зачёт зачёт математика»,
«экзамен математика проект», «проект проект отчёт», «договор поставка проект»,
«договор поставка счёт». Слово «проект» встречается в~разных документах,
поэтому получает меньший вес. Слово «зачёт» встречается только в~первом
документе и~повторяется в~нём два раза, поэтому его вес становится заметно
выше. Поэтому TF-IDF повышает вес более характерных слов и~снижает вес частых
общих слов.

Переход от~текста к~вектору выполняется через общий словарь признаков. Для этого
примера можно взять словарь \(V\): «зачёт», «экзамен», «математика», «проект»,
«отчёт», «договор», «поставка», «счёт». Каждая координата вектора соответствует
одному слову из~этого словаря. Если слово есть в~документе, в~координату
записывается его вес TF-IDF; если слова нет, записывается ноль.

При \(N=5\) слово «зачёт» встречается в~одном документе, поэтому его
множитель IDF равен \(\ln(5/(1+1))\approx0{,}916\). В~первом документе
оно встретилось дважды, значит координата для этого слова равна
\(2\cdot0{,}916=1{,}832\). Слово «математика» встречается в~двух документах
и~получает вес \(\ln(5/(2+1))\approx0{,}511\), а~слово «проект» встречается
в~трёх документах и~получает меньший вес
\(\ln(5/(3+1))\approx0{,}223\). Тогда полный вид векторов в~порядке слов
из~словаря \(V\) будет следующим:
\[
    \begin{aligned}
        d_1 &= (1{,}832;\,0;\,0{,}511;\,0;\,0;\,0;\,0;\,0),\\
        d_2 &= (0;\,0{,}916;\,0{,}511;\,0{,}223;\,0;\,0;\,0;\,0),\\
        d_3 &= (0;\,0;\,0;\,0{,}446;\,0{,}916;\,0;\,0;\,0),\\
        d_4 &= (0;\,0;\,0;\,0{,}223;\,0;\,0{,}511;\,0{,}511;\,0),\\
        d_5 &= (0;\,0;\,0;\,0;\,0;\,0{,}511;\,0{,}511;\,0{,}916).
    \end{aligned}
\]
После такого преобразования обычные тексты становятся числовыми объектами, к~ним
можно применять меры расстояния и~алгоритмы классификации.

Чтобы сравнить два документа по~их векторам, часто используют косинусную
близость:
\begin{equation}
    \label{eq:cosine}
    \cos(a,b) =
    \frac{\sum_{j=1}^{m} a_j b_j}
    {\sqrt{\sum_{j=1}^{m} a_j^2}\sqrt{\sum_{j=1}^{m} b_j^2}}.
\end{equation}
В~формуле \( a \) и~\( b \) "--- векторы двух документов, \( a_j \) и~\( b_j \)
"--- значения \( j \)-го признака, \( m \) "--- число признаков. Если значение
близко к~единице, документы похожи по~набору признаков. Если значение близко
к~нулю, документы мало похожи.

Подсчёт слов плохо учитывает смысл. Например, документы «оплата счёта»
и~«платёж по договору» могут относиться к~одной теме, хотя совпадающих слов
мало. Для таких случаев применяются эмбеддинги. Эмбеддинг "--- это числовой
вектор текста, в~котором похожие по~смыслу тексты должны находиться рядом.

Первые широко используемые модели строили векторы отдельных слов. К~ним
относятся word2vec и~fastText~\autocite{Mikolov2013word2vec,Bojanowski2017fastText}.
Они обучались на~большом корпусе без ручных меток: модель предсказывала слово
по~его соседям или соседние слова по~данному слову. Поэтому слова, которые часто
встречались в~похожем окружении, получали близкие векторы. fastText дополнительно
учитывает части слова, поэтому лучше работает с~редкими словами и~словоформами.
Но~вектор одного слова не~всегда достаточно хорошо описывает целый документ.

Дальше появились модели, которые учитывают контекст слова в~предложении.
BERT использует архитектуру Transformer и~механизм внимания: при~обучении
модель видит предложение с~частью скрытых слов и~учится восстанавливать их
по~левому и~правому контексту. Поэтому представление слова зависит от~его
окружения, а~не~только от~самого слова. Например, в~предложениях «дверной
замок сломался» и~«старый замок стоит на~горе» одно и~то~же слово получает
разные представления, потому что используется в~разных смыслах
\autocite{Devlin2019BERT}. Sentence-BERT использует похожую основу, но~сразу
получает вектор предложения или короткого текста, который удобно сравнивать
по~косинусной близости~\autocite{Reimers2019SBERT}. Современные эмбеддинги,
полученные от~трансформеров, обычно имеют большую размерность: текст описывается
не~несколькими, а~сотнями или тысячами числовых координат. Для документов
на~разных языках применяются многоязычные модели, например многоязычные варианты
Sentence-BERT, LaBSE и~BGE-M3
\autocite{Reimers2020MultilingualSBERT,Feng2022LaBSE,Chen2024BGEM3}.

На~простом примере эмбеддинги можно представить как~карту. Документы
«сдать лабораторную работу» и~«подготовить отчёт по предмету» должны оказаться
рядом, потому что оба связаны с~учёбой. Документ «оплатить счёт за услуги»
окажется дальше, потому что относится к~финансам. Такой способ удобен для
классификации и~для поиска групп похожих документов.

\section{Способы разбиения текстовых данных на группы}\label{sec:ch1/cluster}

Кластеризация "--- это разбиение объектов на~группы без заранее известных
меток. В~задаче с~документами она полезна, когда разметки ещё нет или её мало.
Алгоритм получает векторы документов и~пытается найти группы похожих текстов.
Полученные группы можно показать человеку, чтобы он дал им названия.

Простой метод кластеризации "--- \( k \)-means~\autocite{MacQueen1967KMeans}.
Пользователь заранее задаёт число групп \( K \). Алгоритм выбирает центры
групп, относит каждый объект к~ближайшему центру, затем пересчитывает центры
и~повторяет эти действия.

Цель \( k \)-means можно записать так:
\begin{equation}
    \label{eq:kmeans}
    J = \sum_{i=1}^{N} \left\| z_i - c_{r_i} \right\|^2.
\end{equation}
Здесь \( J \) "--- суммарная ошибка разбиения, \( N \) "--- число документов,
\( z_i \) "--- вектор \( i \)-го документа, \( c_{r_i} \) "--- центр группы,
к~которой отнесён документ \( i \), \( r_i \) "--- номер этой группы, а
\( \left\| z_i - c_{r_i} \right\|^2 \) "--- квадрат расстояния от~документа
до~центра его группы. Алгоритм старается сделать \( J \) как~можно меньше.

Допустим, есть шесть точек на~плоскости. Точки A, B и~C лежат
рядом с~координатой \((1;1)\), а~точки D, E и~F лежат рядом с~координатой
\((5;5)\). Если задать \( K=2 \), \( k \)-means найдёт два центра и~разделит
точки на~две группы.
Если же задать \( K=3 \), алгоритм всё равно создаст три группы, даже если
по~данным естественно видны только две. Это главный недостаток метода.

Плотностные методы ищут области, где точки стоят близко друг к~другу. DBSCAN
использует два параметра: радиус \( \varepsilon \) и~минимальное число соседей
\( m \)~\autocite{Ester1996DBSCAN}. Окрестность точки \( p \) задаётся так:
\begin{equation}
    \label{eq:eps-neighborhood}
    N_{\varepsilon}(p) = \{\,q \in Z \mid \operatorname{dist}(p,q) \leqslant \varepsilon\,\}.
\end{equation}
Здесь \( N_{\varepsilon}(p) \) "--- множество соседей точки \( p \),
\( Z \) "--- множество всех точек, \( q \) "--- другая точка из~этого множества,
\( \operatorname{dist}(p,q) \) "--- расстояние между точками \( p \) и~\( q \),
а~\( \varepsilon \) "--- максимальное расстояние, при~котором точки считаются
соседями.

Если у~точки достаточно соседей внутри радиуса \( \varepsilon \), она становится
ядром группы. От~таких точек группа расширяется на~соседей. Точки, которые
не~попали ни~в~одну плотную область, помечаются как~шум. Например, рассмотрим
четыре двумерные точки: \(p_1=(0;0)\), \(p_2=(0{,}1;0)\),
\(p_3=(0;0{,}1)\) и~\(p_4=(3;3)\). При~\(\varepsilon=0{,}2\) и~\(m=3\)
первые три точки попадают в~одну плотную область, потому что находятся близко
друг к~другу, а~точка \(p_4\) остаётся отдельной и~может быть помечена как~шум.

HDBSCAN развивает эту идею и~не~требует одного общего радиуса для всех групп
\autocite{Campello2013HDBSCAN,McInnes2017HDBSCAN}. Метод смотрит на~данные при
разных уровнях плотности и~оставляет устойчивые группы. Для сравнения точек
используется расстояние взаимной достижимости:
\begin{equation}
    \label{eq:mreach}
    d_{\mathrm{mreach}}(a,b) =
    \max\{\,\mathrm{core}_m(a),\ \mathrm{core}_m(b),\ d(a,b)\,\}.
\end{equation}
Здесь \( d_{\mathrm{mreach}}(a,b) \) "--- расстояние взаимной достижимости
между точками \( a \) и~\( b \), \( \mathrm{core}_m(a) \) "--- расстояние
от~точки \( a \) до~её \( m \)-го ближайшего соседа, \( \mathrm{core}_m(b) \)
"--- такое~же расстояние для точки \( b \), \( d(a,b) \) "--- обычное расстояние
между \( a \) и~\( b \), а~\( \max \) выбирает наибольшее из~трёх значений.

На~простых данных это можно понять так. В~плотной группе ближайшие соседи
находятся совсем рядом, поэтому расстояние взаимной достижимости почти совпадает
с~обычным расстоянием. У~одинокой точки ближайшие соседи далеко, поэтому её
расстояние до~других точек становится большим. Благодаря этому HDBSCAN легче
отделяет устойчивые группы от~шума.

\section{Уменьшение размерности эмбеддингов}\label{sec:ch1/umap}

Эмбеддинг документа обычно имеет сотни или тысячи координат. Такая размерность
появляется потому, что трансформер хранит результат обработки текста в~скрытом
пространстве модели: каждая координата участвует в~описании смысла, контекста и
лексических признаков, но~редко соответствует одному понятному человеку
свойству. В~таком пространстве данные нельзя напрямую показать на~рисунке,
а~поиск групп становится менее устойчивым: лишние и~шумовые координаты могут
искажать расстояния между документами.

Снижение размерности переводит эмбеддинги в~меньшее число координат. Для
визуализации обычно выбирают две или три координаты, чтобы построить рисунок.
Для кластеризации часто оставляют больше координат, чем для рисунка, но~меньше,
чем в~исходном эмбеддинге. Это помогает убрать часть шума и~избыточных
направлений, сохранить главную структуру соседства и~сделать расстояния между
документами более полезными для методов \( k \)-means, DBSCAN и~HDBSCAN.
Без такого шага алгоритм может группировать документы по~случайным отличиям
в~сотнях координат, а~не~по~устойчивым тематическим признакам.

UMAP строит граф ближайших соседей: для каждой точки он ищет похожие точки,
а~потом пытается перенести эту структуру в~пространство меньшей размерности
\autocite{McInnes2018UMAP}. Если три документа были близки в~исходных векторах,
на~двумерной схеме они тоже должны оказаться рядом. Например, документы про
«зачёт», «лабораторную работу» и~«экзамен» могут лечь в~одну область, а~документы
про «счёт», «оплату» и~«договор» "--- в~другую.

\section{Метрики и качество кластеризации}\label{sec:ch1/metrics}

Кластеризацию сложнее оценивать, чем классификацию, потому что правильные метки
часто заранее неизвестны. Поэтому используют внутренние метрики, которые
смотрят на~расстояния между точками.

Коэффициент силуэта (silhouette score) показывает, насколько объект похож на~свою группу и~насколько
он далёк от~соседней группы~\autocite{Rousseeuw1987Silhouette}:
\begin{equation}
    \label{eq:silhouette}
    s_i = \frac{b_i - a_i}{\max(a_i,b_i)}.
\end{equation}
Здесь \( s_i \) "--- силуэт для объекта \( i \), \( a_i \) "--- среднее расстояние
от~объекта \( i \) до~объектов своей группы, \( b_i \) "--- среднее расстояние
от~объекта \( i \) до~ближайшей другой группы, а~\( \max(a_i,b_i) \) "--- большее
из~двух значений. Значение ближе к~единице означает, что объект хорошо лежит
в~своей группе. Значение около нуля показывает пограничный случай.

Индекс Дэвиса"--~Боулдина (DBI) сравнивает внутрикластерный разброс и~расстояние
между группами~\autocite{Davies1979DBI}. Пусть \( C_r \) "--- \( r \)-я группа,
\( c_r \) "--- её центр, \( K \) "--- число групп, а~\( d(\cdot,\cdot) \) "---
выбранная метрика расстояния. Тогда:
\begin{equation}
    \label{eq:davies-bouldin}
    \begin{aligned}
        S_r &= \frac{1}{|C_r|}\sum_{z_i\in C_r} d(z_i,c_r),\\
        M_{rs} &= d(c_r,c_s),\\
        R_{rs} &= \frac{S_r + S_s}{M_{rs}},\\
        \operatorname{DBI} &= \frac{1}{K}\sum_{r=1}^{K}\max_{s\ne r} R_{rs}.
    \end{aligned}
\end{equation}
Величина \( S_r \) показывает, насколько объекты группы разбросаны вокруг центра,
а~\( M_{rs} \) показывает расстояние между центрами двух групп. Отношение
\( R_{rs} \) становится большим, если две группы широкие или их центры находятся
близко. Для каждой группы берётся худший сосед, то~есть группа с~максимальным
\( R_{rs} \), после чего значения усредняются. Поэтому меньший DBI означает
более компактные и~лучше разделённые группы. Индекс удобен для сравнения разных
вариантов кластеризации без правильных меток, но~он опирается на~центры групп и
хуже описывает вытянутые или сложные по~форме кластеры.

Для плотностных методов также используют DBCV (Density-Based Clustering
Validation). Эта метрика оценивает не~центры, а~плотностную связность групп,
поэтому лучше подходит для DBSCAN и~HDBSCAN~\autocite{Moulavi2014DBCV}. Пусть
\( d_{\mathrm{mreach}} \) "--- расстояние взаимной достижимости из
формулы~\eqref{eq:mreach}. Для группы \( C_r \) строится минимальное остовное
дерево по~этим расстояниям. Тогда:
\begin{equation}
    \label{eq:dbcv}
    \begin{aligned}
        \mathrm{DSC}_r
            &= \max_{e\in\mathrm{MST}(C_r)} w(e),\\
        \mathrm{DSPC}_r
            &= \min_{s\ne r}\min_{\substack{z_i\in C_r\\ z_j\in C_s}}
                d_{\mathrm{mreach}}(z_i,z_j),\\
        V_r
            &= \frac{\mathrm{DSPC}_r-\mathrm{DSC}_r}
                {\max(\mathrm{DSPC}_r,\mathrm{DSC}_r)},\\
        \operatorname{DBCV}
            &= \sum_{r=1}^{K}\frac{|C_r|}{n}V_r.
    \end{aligned}
\end{equation}
Здесь \( \mathrm{DSC}_r \) "--- внутренняя разреженность группы: самое тяжёлое
ребро в~её остовном дереве. Если группа растянута цепочкой, это значение растёт.
Величина \( \mathrm{DSPC}_r \) показывает ближайшее плотностное расстояние от
этой группы до~других групп, а~\( n \) "--- число объектов, вошедших в~группы.
Значение \( V_r \) положительно, когда отделение от соседних групп больше
внутренней разреженности, и~отрицательно, когда группа плохо отделена или внутри
неё есть слабая плотностная связь. Итоговый DBCV лежит в~диапазоне от~\(-1\)
до~\(1\); чем он больше, тем лучше плотностная структура кластеризации. Эту
метрику используют для выбора параметров DBSCAN/HDBSCAN и~для сравнения
разбиений, когда правильных меток нет. На~простом примере две плотные группы
и~несколько далёких шумовых точек должны получить оценку лучше, чем разбиение,
где одна группа растянута длинной цепочкой и~почти касается другой.

\section{Классификация на размеченных данных}\label{sec:ch1/clf}

После появления размеченного набора можно обучать классификатор. Разметка
сообщает модели, какие документы относятся к~каким категориям. Дальше модель
ищет признаки, по~которым эти категории отличаются.

Если документ уже представлен эмбеддингом, поверх него можно обучить
классификатор. Классический вариант "--- линейный слой с~функцией softmax.
Пусть \( h=\varphi(d) \) "--- эмбеддинг документа \( d \). Для каждой категории
\( y_k \) модель вычисляет линейный выход
\begin{equation}
    \label{eq:linear-logit}
    a_k = w_k^\top h + b_k,
\end{equation}
где \( w_k \) и~\( b_k \) "--- обучаемые параметры категории. Затем softmax
переводит эти выходы в~оценки, сумма которых равна единице:
\begin{equation}
    \label{eq:softmax}
    p_k(d) = \frac{\exp(a_k)}
    {\sum_{j=1}^{K}\exp(a_j)}.
\end{equation}
Здесь \( p_k(d) \) "--- оценка принадлежности документа \( d \) к~категории
\( y_k \), \( a_k \) "--- числовой выход модели для категории \( y_k \),
\( K \) "--- число категорий, \( j \) "--- номер категории в~сумме, а~\( \exp \)
"--- экспонента. Такой классификатор обучает параметры \( w_k \) и~\( b_k \)
по~размеченным примерам.

При~обучении модель штрафуется за~низкую оценку правильной категории:
\begin{equation}
    \label{eq:cross-entropy}
    L = -\frac{1}{N}\sum_{i=1}^{N}\log p_{y_i}(d_i).
\end{equation}
В~формуле \( L \) "--- ошибка обучения, \( N \) "--- число обучающих документов,
\( i \) "--- номер документа, \( d_i \) "--- \( i \)-й документ, \( y_i \) "---
его правильная категория, \( p_{y_i}(d_i) \) "--- оценка, которую модель дала
правильной категории, а~\( \log \) "--- логарифм. Чем выше оценка правильной
категории, тем меньше ошибка.

Такой вариант удобен, когда набор категорий заранее известен и~меняется редко:
каждой категории соответствует свой выходной узел и~свой набор параметров.
Если в~процессе работы появляются новые классы, последний слой приходится
расширять и~переобучать или дообучать на~обновлённой разметке.

В~данной работе используется другой вариант "--- классификатор поверх
эмбеддингов с~прототипами классов. Он не~обучает новый нейросетевой слой, а
сохраняет для каждого класса один или несколько эталонных векторов. Пусть
\( H_k=\{\widehat{h}_{k,1},\dots,\widehat{h}_{k,n_k}\} \) "--- нормированные
эмбеддинги размеченных документов класса \( y_k \), где \( n_k \) "--- число
таких документов, а~\( \widehat{h}_{k,i} \) "--- нормированный эмбеддинг
\( i \)-го документа этого класса. Нормирование нужно, чтобы сравнение
сильнее зависело от~направления вектора, то~есть от~смысловой близости документа,
а~не~от~масштаба координат. Кроме того, для нормированных векторов скалярное
произведение совпадает с~косинусной близостью. Если класс описывается одной
небольшой областью, его прототип можно вычислить как нормированный центроид:
\begin{equation}
    \label{eq:prototype-centroid}
    \mu_k=\frac{1}{n_k}\sum_{i=1}^{n_k}\widehat{h}_{k,i},
    \qquad
    c_k=\frac{\mu_k}{\lVert\mu_k\rVert_2}.
\end{equation}
Здесь \( \mu_k \) "--- средний вектор класса до~повторного нормирования,
\( n_k \) "--- количество размеченных документов в классе \( y_k \), а
\( c_k \) "--- итоговый прототип класса \( y_k \).

Один класс может состоять из~нескольких тематических подгрупп. Например, класс
«учёба» может включать документы про экзамены, лабораторные работы и~зачёты.
Если заменить такой класс одним центром, часть документов окажется далеко от
прототипа. Поэтому обучающие эмбеддинги класса можно сначала разделить на
подгруппы \( G_{k,m} \), где \( m \) "--- номер подгруппы внутри класса
\( y_k \), а~затем построить прототип для каждой подгруппы:
\begin{equation}
    \label{eq:multi-prototype-centroid}
    \mu_{k,m}=\frac{1}{\lvert G_{k,m}\rvert}
    \sum_{\widehat{h}\in G_{k,m}}\widehat{h},
    \qquad
    c_{k,m}=\frac{\mu_{k,m}}{\lVert\mu_{k,m}\rVert_2}.
\end{equation}
В~этой формуле \( \lvert G_{k,m}\rvert \) "--- число документов в~подгруппе,
\( \mu_{k,m} \) "--- её средний вектор, а~\( c_{k,m} \) "--- \( m \)-й прототип
класса \( y_k \).

Для нового документа \( x \) система строит нормированный эмбеддинг
\( \widehat{\varphi}(x) \) и~сравнивает его с~прототипами. Так как оба вектора
нормированы, скалярное произведение равно косинусной близости. Оценка класса
равна максимальной близости к~его прототипам:
\begin{equation}
    \label{eq:prototype-score}
    s_k(x)=\max_{1\leqslant m\leqslant M_k}
    \bigl\langle \widehat{\varphi}(x), c_{k,m}\bigr\rangle.
\end{equation}
Здесь \( M_k \) "--- число прототипов класса \( y_k \), а~\( s_k(x) \) "---
оценка близости документа \( x \) к~этому классу.
Предсказанием становится класс с~наибольшей оценкой. Решающее правило повторяет
идею порога из~формулы~\eqref{eq:decision-rule}, но~использует не~вероятность,
а~косинусную близость к~прототипам:
\begin{equation}
    \label{eq:prototype-decision}
    a_{\tau}^{\mathrm{proto}}(x) =
    \begin{cases}
        \arg\max\limits_{k \in Y} s_k(x),
        & \text{если } \max\limits_{k \in Y} s_k(x) \geqslant \tau, \\
        \bot,
        & \text{если } \max\limits_{k \in Y} s_k(x) < \tau.
    \end{cases}
\end{equation}
Если максимум ниже порога \( \tau \), система не~назначает пользовательский класс
автоматически. Прототипный подход удобен при~небольшом числе размеченных
документов: новый класс можно добавить через его прототипы, а~письма, далёкие от
известных прототипов, направлять на~ручную проверку.

\section{Метрики качества}\label{subsec:ch1/task/metrics}
\label{subsec:ch1/cluster/metrics}

Метрики нужны, чтобы оценить не~отдельный удачный пример, а~работу модели
на~наборе документов. Для классификации обычно считают долю верных ответов,
точность, полноту и~F1-меру~\autocite{Sokolova2009Metrics,Manning2008IR}.

Для одной категории \( y_k \) вводятся три величины. \( \mathrm{TP}_k \) "---
число документов, которые действительно относятся к~категории \( y_k \) и~были
правильно отнесены к~ней. \( \mathrm{FP}_k \) "--- число документов, которые
модель ошибочно отнесла к~категории \( y_k \). \( \mathrm{FN}_k \) "--- число
документов категории \( y_k \), которые модель пропустила и~отнесла к~другим
категориям.

Точность и~полнота для категории \( y_k \) считаются так:
\begin{align}
    \label{eq:precision}
    \mathrm{Precision}_k & =
    \frac{\mathrm{TP}_k}{\mathrm{TP}_k + \mathrm{FP}_k}, \\
    \label{eq:recall}
    \mathrm{Recall}_k & =
    \frac{\mathrm{TP}_k}{\mathrm{TP}_k + \mathrm{FN}_k}.
\end{align}
Здесь \( \mathrm{Precision}_k \) показывает, какая доля документов, отнесённых
моделью к~категории \( y_k \), действительно принадлежит этой категории.
\( \mathrm{Recall}_k \) показывает, какую долю настоящих документов категории
\( y_k \) модель смогла найти.

F1-мера объединяет точность и~полноту:
\begin{equation}
    \label{eq:f1}
    F_{1,k} =
    \frac{2\cdot \mathrm{Precision}_k \cdot \mathrm{Recall}_k}
    {\mathrm{Precision}_k + \mathrm{Recall}_k}.
\end{equation}
Здесь \( F_{1,k} \) "--- F1-мера для категории \( y_k \). Если точность высокая,
а~полнота низкая, итоговое значение тоже снижается. Поэтому F1-мера полезна,
когда нужно учитывать оба качества сразу.

Для многоклассовой задачи часто используют среднее значение по~категориям:
\begin{equation}
    \label{eq:macro-f1}
    \mathrm{macro\text{-}F_1} =
    \frac{1}{K}\sum_{k=1}^{K} F_{1,k}.
\end{equation}
В~формуле \( \mathrm{macro\text{-}F_1} \) "--- средняя F1-мера по~категориям,
\( K \) "--- число категорий, \( k \) "--- номер категории, \( F_{1,k} \) "---
F1-мера категории \( y_k \). Такая метрика полезна при~несбалансированных
данных, потому что каждая категория получает одинаковый вес.

Доля верных ответов считается проще:
\begin{equation}
    \label{eq:accuracy}
    \mathrm{Accuracy} =
    \frac{1}{N_{\mathrm{test}}}\sum_{i=1}^{N_{\mathrm{test}}}
    \mathbb{1}\bigl[\,\hat{y}_i = y_i\,\bigr].
\end{equation}
Здесь \( \mathrm{Accuracy} \) "--- доля верных ответов, \( N_{\mathrm{test}} \)
"--- число документов в~проверочном наборе, \( i \) "--- номер документа,
\( \hat{y}_i \) "--- предсказанная категория, \( y_i \) "--- правильная
категория, а~\( \mathbb{1}[\cdot] \) равно единице при~верном ответе и~нулю
при~ошибке.

Если используется отказ \texttt{other}, отдельно считается покрытие:
\begin{equation}
    \label{eq:coverage}
    \mathrm{Coverage} =
    \frac{1}{N_{\mathrm{test}}}\sum_{i=1}^{N_{\mathrm{test}}}
    \mathbb{1}\bigl[\,f(x_i) \neq \texttt{other}\,\bigr].
\end{equation}
Здесь \( \mathrm{Coverage} \) "--- доля документов, для которых модель выдала
одну из~обычных категорий, \( x_i \) "--- \( i \)-й документ, \( f(x_i) \) "---
ответ модели для этого документа, а~\texttt{other} "--- отказ от~классификации.
Покрытие нужно смотреть вместе с~F1-мерой. Если покрытие очень высокое, но~много
ошибок, система слишком часто принимает слабые решения. Если покрытие слишком
низкое, система часто отказывается от~ответа.

Для кластеризации используются другие показатели: силуэт, индекс
Дэвиса"--~Боулдина, DBCV, число найденных групп, размеры групп и~доля шумовых
объектов. Эти показатели не~заменяют ручную проверку, но~помогают понять,
получились ли группы плотными и~отделёнными друг от~друга.

\section{Постановка задачи разработки}\label{sec:ch1/dev}

На~основе рассмотренных подходов задача разработки сводится к~созданию локальной
системы, которая принимает текстовые документы, подготавливает их, строит
числовые представления, помогает получить категории и~классифицирует новые
документы с~оценкой уверенности.

\subsection{Список задач разработки}\label{subsec:ch1/dev/tasks}

Для решения поставленной задачи нужно выполнить следующие шаги.

\begin{enumerate}
    \item Подготовить текстовые документы к~обработке. Ожидаемый результат:
        из~каждого документа получен очищенный текст в~едином формате.
    \item Описать и~проверить набор данных. Ожидаемый результат: известны
        категории, число документов, распределение по~категориям и~основные
        проблемы данных.
    \item Построить числовые представления документов. Ожидаемый результат:
        каждый документ представлен вектором, который можно сравнивать
        с~другими векторами.
    \item Найти группы похожих документов. Ожидаемый результат: получены
        кластеры документов и~выделены документы, которые плохо входят
        в~устойчивые группы.
    \item Подготовить размеченное множество. Ожидаемый результат: у~документов
        есть проверенные человеком категории для обучения и~оценки модели.
    \item Обучить классификатор на~размеченных данных. Ожидаемый результат:
        модель выдаёт категорию документа и~оценку уверенности.
    \item Настроить отказ от~классификации. Ожидаемый результат: документы
        с~низкой уверенностью получают метку \texttt{other}, а~не~случайную
        известную категорию.
    \item Оценить качество работы. Ожидаемый результат: рассчитаны метрики
        классификации и~кластеризации, а~также сформулированы выводы
        по~полученным значениям.
\end{enumerate}

\subsection{Критерии успеха}\label{subsec:ch1/dev/success}

Задача считается решённой, если выполняются следующие условия.

\begin{enumerate}
    \item Документы обрабатываются локально, без~передачи полного текста
        во~внешние сервисы.
    \item Для документов строятся числовые представления, по~которым можно
        искать похожие тексты и~формировать группы.
    \item Классификатор выдаёт категорию и~оценку уверенности, а~при~низкой
        уверенности возвращает \texttt{other}.
    \item Качество классификации оценивается по~accuracy, macro-F1 и~покрытию,
        а~качество группировки "--- по~внутренним метрикам кластеризации
        и~ручной проверке групп.
\end{enumerate}

Итогом анализа является набор требований к~локальной системе классификации:
подготовка текста, построение векторных представлений, группировка похожих
документов, обучение по~разметке, отказ от~слабых решений и~оценка качества
по~нескольким метрикам.
