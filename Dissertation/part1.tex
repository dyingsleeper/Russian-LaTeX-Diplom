\chapter{Анализ задачи и обзор существующих решений}\label{ch:problem}

Текстовые документы хранят учебные материалы, рабочие файлы, отчёты,
инструкции, заметки и~другие сведения. Когда таких документов становится много,
ручная раскладка по~папкам начинает занимать заметное время. Поиск по~названию
или отдельным словам помогает найти известный файл, но~не~решает задачу
постоянного распределения документов по~смысловым категориям. Для этого нужна
автоматическая классификация, то~есть отнесение документа к~одной из~заранее
понятных групп.

\section{Постановка проблемы}\label{sec:ch1/domain}

Документом в~данной задаче считается текстовая запись, которую можно прочитать
и~обработать программно. Категорией называется понятная
пользователю группа документов: например, «учёба», «работа», «договоры»,
«отчёты» или «личные заметки». Категория нужна не~сама по~себе, а~для более
быстрого поиска и~порядка в~архиве.

Простейший способ организации документов "--- ручное создание папок и~перенос
файлов. Такой способ хорошо работает при~малом числе документов. Если же архив
пополняется каждый день, пользователь начинает тратить время на~однотипные
действия. Часть документов попадает не~в~ту папку, часть остаётся без категории,
а~один и~тот~же документ иногда подходит сразу под несколько признаков.

Поиск и~фильтры решают только часть проблемы. Поиск требует, чтобы пользователь
помнил слово из~документа или его название. Фильтр требует заранее заданного
правила. Но~в~тексте может не~быть точного ключевого слова, хотя по~смыслу
документ относится к~нужной теме. Также фильтры должны иметь заранее заданные
категории, по которым будет производиться сортировка, что добавляет сложность
конечному пользователю для организации своих документов. Поэтому со~временем
начали применять методы, которые учитывают не~только отдельные слова,
но~и~похожесть документов между собой.

Система, которая автоматически сортирует документы и~предлагает дополнить
имеющиеся категории новыми, получает доступ к~содержимому пользовательского
архива. В~таком архиве часто находятся личные данные, учебные работы, рабочие
материалы или внутренние сведения организации. При передаче этих текстов
во~внешний сервис пользователь теряет прямой контроль над~тем, где они хранятся
и~как обрабатываются. Поэтому для такой системы важна локальная обработка:
текст остаётся на~устройстве пользователя или внутри его инфраструктуры.

\section{Обзор существующих подходов и решений}\label{sec:ch1/systems}

Подходы к~сортировке текстовых документов развивались постепенно. Сначала
использовались ручные правила и~ключевые слова. Затем стали применять
вероятностные методы, которые учатся по~готовым примерам. Позже появились
нейронные модели, способные строить числовое представление целого текста и~по
нему сравнивать документы по~смыслу~\autocite{Sebastiani2002TextCat,Kowsari2019TextSurvey}.

Ниже приведены примеры таких подходов. Каждый пример показывает отдельный
способ сортировки текста: от~простых правил до~обучения по~готовым примерам.

\textbf{Sieve} "--- язык правил для сортировки сообщений при~их доставке.
В~RFC~5228 он описывается как простой и~ограниченный язык: пользователь задаёт
проверки и~действия, а~система выполняет их по~порядку~\autocite{Guenther2008Sieve}.
Проверка может смотреть на~адрес отправителя, заголовок, размер сообщения или
наличие нужной строки. Действие указывает, что сделать дальше: оставить
сообщение, переложить его в~папку, переслать или удалить. Например, правило
может звучать так: если в~заголовке есть слово «отчёт», переложить сообщение
в~папку «отчёты». Такой подход легко объяснить пользователю, но~он плохо
понимает смысл текста. Если нужная мысль выражена другими словами, правило
может не~сработать.

\textbf{Байесовский фильтр спама} "--- способ отличать спам от~обычных
сообщений по~словам, которые встречались в~размеченных примерах. В~работе
по~байесовской фильтрации спама такой фильтр строится на~наивном
байесовском классификаторе: сначала берутся сообщения с~готовыми метками
«спам» и~«не~спам», затем для слов оценивается их связь с~каждым классом
\autocite{Androutsopoulos2000NaiveBayesSpam}. Если слово часто встречалось
в~спаме, оно получает больший вес для класса «спам». Если слово чаще
встречалось в~обычных сообщениях, оно получает больший вес для второго класса.
При проверке нового сообщения фильтр складывает влияние найденных слов
и~получает общий балл. Если этот балл выше заданной границы, сообщение
попадает в~спам. Такой метод уже учится на~примерах, но~обычно решает задачу
с~двумя классами, а~для сортировки документов часто нужно больше категорий.

\textbf{Gmail Priority Inbox} "--- способ поднять важные сообщения выше
остальных. В~статье о~Gmail Priority Inbox он описывается как система
обучения, которая смотрит на~признаки сообщения и~на~действия пользователя
\autocite{Aberdeen2010PriorityInbox}.
К~признакам относятся отправитель, получатели, слова в~сообщении и~другие
данные, доступные почтовому сервису. Действия пользователя тоже важны: какие
сообщения он открывает, на~какие отвечает, какие помечает как важные или
неважные. На~основе этих сигналов система решает, стоит ли показать сообщение
в~более заметной части списка. Такой подход снижает ручную работу, но~он
делит сообщения по~важности, а~не~по~пользовательским смысловым категориям.

\textbf{Outlook Focused Inbox} "--- встроенная сортировка сообщений на~две
вкладки: Focused и~Other. В~документации сервиса указано, что система
помещает важные сообщения во~вкладку Focused, а~остальные показывает
во~вкладке Other~\autocite{Microsoft2024FocusedInbox}. При этом она учитывает
контакты и~действия пользователя. Если пользователь вручную переносит
сообщение между вкладками, сервис использует это действие как подсказку
для~будущей сортировки. По~смыслу это похоже на~обучение по~обратной связи:
пользователь исправляет решение, а~система старается повторить такой выбор
позже. Ограничение остаётся тем~же: сервис даёт только две группы и~работает
в~рамках готовой почтовой среды.

\textbf{TaskTracer} "--- исследовательская система, в~которой сообщения
связываются с~проектами пользователя. В~работе о~TaskTracer сравниваются
алгоритмы, которые обучаются по~мере поступления новых примеров
\autocite{Keiser2009TaskTracer}. Такой режим можно объяснить просто: сначала
пользователь показывает системе несколько сообщений для каждого проекта, затем
система относит новые сообщения к~похожим проектам, а~после исправлений
обновляет свои знания. Например, если сообщения со~словами «договор»,
«смета» и~«подпись» часто относились к~одному проекту, похожее новое сообщение
получит тот~же проект. TaskTracer ближе к~задаче классификации, но~он
рассматривает заранее известные проекты и~почтовые сообщения, а~не~общий
архив текстовых документов.

\textbf{EmFORE} "--- метод автоматического построения правил для распределения
сообщений по~папкам. В~статье о~EmFORE предлагается обучать правила на~тех
папках, которые уже есть у~пользователя, и~обновлять эти правила, когда поток
сообщений меняется~\autocite{Singh2023EmFORE}. Правило может учитывать
отправителя, слова в~теме и~другие признаки. Например, если пользователь часто кладёт
сообщения с~одного адреса и~с~похожей темой в~папку проекта, система может
создать похожее правило сама. Плюс такого подхода в~том, что правило можно
прочитать и~понять. Минус в~том, что классы берутся из~существующих папок,
поэтому система зависит от~того, как пользователь уже организовал свой архив.

Эти примеры показывают, что готовые решения закрывают только часть задачи.
Ручные правила понятны, но~требуют постоянной поддержки. Вероятностные методы
и~обучение по~примерам лучше работают с~разными формулировками, но~зависят
от~качества разметки. Сервисы сортировки сообщений помогают в~своей среде,
однако они не~дают полноценную локальную сортировку произвольных текстовых
документов по~нескольким смысловым группам.

\section{Классификация текстовых документов}\label{sec:ch1/classification}

\subsection{Постановка задачи классификации}\label{subsec:ch1/classification/placing_probleb}

Задача классификации текстовых документов формулируется как задача построения
правила, которое сопоставляет документу одну из~заданных категорий. Для такой
постановки последовательно задаются пространство объектов \( X \), множество
классов \( Y \), обучающая выборка \( D \), алгоритм классификации \( a \)
и~вероятностная модель \( p(y \mid x) \).

Пространство объектов \( X \) задаёт множество элементов, допустимых
для~обработки системой. Элемент \( x \in X \) обозначает один текстовый
документ после извлечения основного текста и~приведения его к~единому виду.
В~рамках работы объектом классификации является документ, который должен быть
отнесён к~одной пользовательской категории.

Множество классов \( Y \) задаёт набор допустимых категорий. Формально
используется конечное множество \( Y = \{c_1, c_2, \ldots, c_K\} \), где
\( K \) "--- число категорий. Каждый элемент \( c_k \in Y \) соответствует
одному классу документов, определённому пользователем.

Обучающая выборка \( D \) представляет собой набор размеченных
примеров:
\begin{equation}
    D = \{(x_i, y_i)\}_{i=1}^{n}, \quad x_i \in X,\ y_i \in Y.
\end{equation}
В~паре \( (x_i, y_i) \) документ \( x_i \) является объектом классификации,
а~метка \( y_i \) задаёт известный класс этого документа. По~таким парам
строится правило классификации для~документов, метки которых заранее
не~известны.

Алгоритм классификации \( a \) определяется как отображение
\begin{equation}
    a: X \rightarrow Y.
\end{equation}
Значение \( a(x) \) является классом, который алгоритм назначает документу
\( x \). Следовательно, обучение классификатора состоит в~построении
отображения \( a \) по~обучающей выборке \( D \).

Вероятностная модель классификации задаёт для~документа \( x \)
условное распределение классов \( p(y \mid x) \). В~этой постановке метка
\( y \) рассматривается как дискретная случайная величина со~значениями
из~множества \( Y \). Для~каждого класса \( c_k \in Y \) величина
\( p(y = c_k \mid x) \) интерпретируется как оценка принадлежности документа
\( x \) классу \( c_k \).

\subsection{Многоклассовая классификация с отказом от решения}\label{subsec:ch1/classification/multiclass}\label{sec/multitask}

Многоклассовая классификация отличается от общего вида тем, что количество классов \( K \)
подчиняется ограничению \( K > 2 \). Если \( Y = \{1, 2, \ldots, K\} \),
где \( K > 2 \), то для~каждого документа \( x \) нужно выбрать один из~\( K \)
возможных классов. Например, документ может относиться к~категории «учёба»,
«работа», «финансы», «личное» и~так далее.

Пусть для~документа \( x \) известно условное распределение \( p(y \mid x) \).
Тогда для~каждого класса \( k \in Y \) можно рассмотреть число \( p(k \mid x) \).
Это число показывает, насколько вероятно, что документ \( x \) относится именно
к~классу \( k \). Так как один документ должен быть отнесён ровно к~одному
классу, выполняется условие
\begin{equation}
    \label{eq:equation4}
    \sum_{k=1}^{K} p(k \mid x) = 1.
\end{equation}

Если система обязана всегда выбрать некоторый класс, то естественное правило
классификации имеет вид
\begin{equation}
    \label{eq:equation5}
    a(x) = \arg\max_{k \in Y} p(k \mid x).
\end{equation}
То есть алгоритм выбирает тот класс, для~которого вероятность максимальна.

Введем понятие уверенность классификации для~документа \( x \). Оно
показывает вероятность наиболее вероятного класса.
\begin{equation}
    \label{eq:class_confidence}
    \max_{k \in Y} p(k \mid x)
\end{equation}

Однако на~практике не~всегда нужно требовать от~системы обязательного выбора
класса. Для~некоторых документов распределение \( p(y \mid x) \) может быть
неопределённым. Например, если система получила значения
\begin{equation}
    \label{eq:equation7}
    p(\text{«работа»} \mid x) = 0.51,
    \qquad
    p(\text{«финансы»} \mid x) = 0.49,
\end{equation}
то формально класс «работа» имеет наибольшую вероятность. Но разница между
двумя классами мала, поэтому такое решение нельзя считать достаточно надёжным.
В~подобной ситуации лучше не~выбирать класс автоматически, а~передать документ
пользователю для~ручной разметки.

Для~описания такой ситуации вводится специальное решение отказа. Обозначим его
через \( \bot \). Тогда алгоритм классификации принимает значения не~только
из~множества классов \( Y \), но~и~из~множества
\begin{equation}
    \label{eq:equation8}
    Y \cup \{\bot\}.
\end{equation}
Если \( a(x) = \bot \), то это означает, что система отказалась от~автоматического
решения для~документа \( x \).

Простейшее правило классификации с~отказом задаётся с~помощью порога
\( \tau \in [0,1] \). Алгоритм выбирает класс только тогда, когда максимальная
вероятность достаточно велика:
\begin{equation}
    \label{eq:decision-rule}
    a_{\tau}(x) =
    \begin{cases}
        \arg\max\limits_{k \in Y} p(k \mid x),
        & \text{если } \max\limits_{k \in Y} p(k \mid x) \geqslant \tau, \\
        \bot,
        & \text{если } \max\limits_{k \in Y} p(k \mid x) < \tau.
    \end{cases}
\end{equation}
Параметр \( \tau \) называется порогом отказа. Чем больше значение \( \tau \),
тем чаще алгоритм будет отказываться от~решения. Чем меньше значение \( \tau \),
тем больше документов будет классифицировано автоматически, но~тем выше риск
ошибочной классификации.

Это правило можно интерпретировать через вероятность ошибки. Если для~документа
\( x \) выбран класс \( k^* = \arg\max_{k \in Y} p(k \mid x) \),
то вероятность того, что выбранный класс окажется неверным, равна
\begin{equation}
    \label{eq:equation11}
    1 - p(k^* \mid x).
\end{equation}
Следовательно, отказ от~решения нужен тогда, когда эта величина слишком велика.
Например, условие
\begin{equation}
    \label{eq:equation12}
    p(k^* \mid x) \geqslant \tau
\end{equation}
эквивалентно условию
\begin{equation}
    \label{eq:equation13}
    1 - p(k^* \mid x) \leqslant 1 - \tau.
\end{equation}
То есть алгоритм принимает автоматическое решение только в~том случае, если
оценка вероятности ошибки не~превышает заданного уровня.

В~задаче пользовательской классификации документов отказ от~решения имеет
практический смысл. Если документ похож сразу на~несколько категорий или плохо
похож на~все известные категории, система не~должна обязательно выбирать одну
из~них. Вместо этого она может вернуть специальный ответ \( \bot \), после чего
пользователь сам укажет правильную категорию. Такой подход уменьшает число
ошибочных автоматических решений и~позволяет отделить надёжные классификации
от~сомнительных.

\subsection{Классификация на размеченных данных}\label{subsec:ch1/classification/classification_alghorythms}\label{sec:ch1/clf}

Если для некоторого набора элементов уже известны категории, по этим примерам
можно строить классификатор. Пары \( (x_i,y_i) \) показывают, какие признаки
элемента связаны с~каждой категорией. Далее
\( \psi(x) \in \mathbb{R}^{M} \) обозначает числовое представление элемента,
где \( M \) "--- число признаков.

\textbf{Наивный байесовский классификатор} оценивает вероятность класса по
значениям признаков элемента~\autocite{McCallum1998NaiveBayes}. Метод
предполагает, что признаки условно независимы при известном классе. Для вектора
признаков \( v=(v_1,\ldots,v_M) \), где \( v_j \) задаёт значение признака
\( t_j \), правило классификации можно записать в логарифмическом виде:
\begin{equation}
    \label{eq:naive-bayes}
    a(v)=\arg\max_{c_k\in Y}
    \left(
        \log P(c_k) + \sum_{j=1}^{M} v_j \log P(t_j \mid c_k)
    \right).
\end{equation}
Здесь \( P(c_k) \) "--- априорная вероятность класса, а
\( P(t_j \mid c_k) \) "--- вероятность признака \( t_j \) внутри класса
\( c_k \). Такой классификатор прост и хорошо работает с~разреженными
признаковыми описаниями, но~он слабо учитывает зависимости между признаками.

\textbf{Линейный метод опорных векторов} строит разделяющие гиперплоскости
в~пространстве признаков~\autocite{Joachims1998SVMTextCat}. Для многоклассовой
задачи его часто применяют по схеме «один против всех»: для каждого класса
\( c_k \) вычисляется оценка
\begin{equation}
    \label{eq:linear-svm-score}
    s_k(x)=w_k^\top \psi(x)+b_k.
\end{equation}
В~формуле \( w_k \) "--- вектор весов класса, \( b_k \) "--- свободный член,
а~\( s_k(x) \) "--- расстояние до~разделяющей границы с~учётом знака. Элемент
относят к~классу с~наибольшей оценкой. Метод подходит для
высокоразмерных разреженных представлений и~устойчив к~множеству нерелевантных
признаков, но~при изменении набора классов или добавлении большого числа
примеров его обычно нужно переобучать.

\textbf{Логистическая регрессия (Logistic Regression)} также использует
линейную оценку класса, но~интерпретирует результат как вероятность
принадлежности элемента к~классу~\autocite{Fan2008LIBLINEAR}. Для каждого
класса \( c_k \) вычисляется значение
\begin{equation}
    \label{eq:logistic-score}
    z_k(x)=w_k^\top \psi(x)+b_k.
\end{equation}
Здесь \( w_k \) "--- вектор весов класса, \( b_k \) "--- свободный член,
а~\( z_k(x) \) "--- линейная оценка элемента \( x \). В~многоклассовом случае
эти оценки можно преобразовать в~вероятности:
\begin{equation}
    \label{eq:logistic-softmax}
    p(y=c_k \mid x)=
    \frac{\exp(z_k(x))}
    {\sum_{\ell=1}^{K}\exp(z_{\ell}(x))}.
\end{equation}
Класс выбирается по~наибольшей вероятности. Логистическая регрессия даёт
интерпретируемые веса признаков и~вероятностную оценку ответа, но~сохраняет
ограничение линейной модели.

В~совокупности эти методы показывают несколько способов классификации
на~размеченных данных: вероятностную модель признаков, разделяющую границу
и~линейную модель с~вероятностным выходом.

\section{Требования к данным}\label{sec:ch1/data}

Данные для классификации должны быть подготовлены так, чтобы~алгоритм мог
сопоставить признаки текста с~категорией. Набор данных состоит из~документов
и~меток. Метка "--- это правильная категория, назначенная документу человеком.
Без таких примеров классификатор не~может отличать одну категорию от~другой.

Для обучения и~проверки классификатора данные должны удовлетворять нескольким
условиям. Текст должен быть извлечён из~документа в~едином виде. Если один файл
хранится как~обычный текст, другой как~HTML, а~третий как~выгрузка из~таблицы,
их нужно привести к~общему текстовому представлению. Категории должны иметь
ясные границы. Если категории пересекаются слишком сильно, например «работа»
и~«важное», одни и~те~же документы могут получать разные метки.

Желательно, чтобы в~каждой категории было достаточно примеров. Если категория
содержит один или два документа, классификатор будет опираться на~случайные
слова из~этих документов, а~не~на~общий признак категории. Также полезно
отделять часть размеченных документов для проверки. Тогда классификатор
строится на~одной части набора, а~качество считается на~другой части, которая
не~использовалась при~построении правила классификации.

Перед обучением числовые признаки часто приводят к~единому масштабу. Для текста
это может означать нормирование вектора документа: после такой операции длина
вектора становится одинаковой для всех документов, и~при~сравнении сильнее
учитывается направление вектора, а~не~размер текста. Это важно, потому что
длинный документ не~должен получать преимущество только из-за большого числа
слов.

\section{Предобработка и нормализация текстов}\label{sec:ch1/preprocess}

Предобработка "--- это подготовка текста к~построению признаков. Она не~делает
классификацию сама, но~снижает влияние служебных и~случайных элементов
в~данных. К~ним относятся лишние пробелы, повторы, технические строки,
служебные пометки, одинаковые подписи и~случайные символы.

Обычно предобработка включает несколько шагов~\autocite{Manning2008IR}. Сначала
из~файла извлекается основной текст. Затем удаляются лишние пробелы, перевод
строк приводится к~одному виду, а~текст может переводиться в~нижний регистр.
После этого текст делится на~токены. Токеном называется отдельная часть текста,
чаще всего слово или знак. Для русского языка иногда применяют лемматизацию:
слова «документ», «документа» и~«документом» приводятся к~одной начальной форме.

Нормализация должна быть адекватной. Если удалить слишком много, можно потерять
важные признаки. Например, номер договора, дата или название проекта иногда
помогают определить категорию. Поэтому правила очистки текста подбираются под
тип документов, а~не~применяются вслепую.

\section{Способы представления текста для алгоритмов машинного обучения}\label{sec:ch1/repr}

Числовое представление текста "--- это отображение документа
в~пространство числовых признаков:
\[
    \varphi: X \rightarrow \mathbb{R}^{m}.
\]
Здесь \( X \) обозначает множество текстовых документов, \( m \) "--- число
признаков, а~\( \varphi(x) \) "--- вектор документа \( x \). После такого
преобразования классификатор получает на~вход не~исходный текст, а~числовой
вектор фиксированной структуры.

Словарь признаков \( V \) задаёт множество текстовых единиц,
используемых при~векторизации. Элементами словаря являются слова, леммы или
токены. Если \( V = \{t_1, t_2, \ldots, t_m\} \), то \( j \)-я координата
вектора документа соответствует признаку \( t_j \).

\textbf{Мешок слов} (Bag-of-Words) представляет документ частотами словаря.
Для документа \( d \) координата \( j \) равна числу вхождений признака
\( t_j \) в~данный документ. В~таком представлении сохраняются частоты
лексических признаков, но~порядок слов и~синтаксические связи не~учитываются.

\textbf{TF-IDF} "--- взвешенное частотное представление текста. Вес признака
возрастает, если слово часто встречается в~документе, и~снижается, если слово
часто встречается во~многих документах набора
\autocite{Salton1988TFIDF,Manning2008IR}:
\begin{equation}
    \label{eq:tfidf}
    w_{t,d} = \mathrm{tf}(t,d)\cdot \ln\frac{N}{n_t + 1}.
\end{equation}
В~формуле \( w_{t,d} \) обозначает вес слова \( t \) в~документе \( d \),
\( \mathrm{tf}(t,d) \) "--- число вхождений слова \( t \) в~документ \( d \),
\( N \) "--- общее число документов в~наборе, \( n_t \) "--- число документов,
содержащих слово \( t \). Единица в~знаменателе предотвращает деление на~ноль
при~расчёте веса для признаков, отсутствующих в~обучающем наборе.

Вектор TF-IDF строится по~общему словарю признаков. В~качестве
примера используется набор из~пяти документов: «зачёт зачёт математика»,
«экзамен математика проект», «проект проект отчёт», «договор поставка проект»,
«договор поставка счёт».
Для данного набора используется словарь \( V \): «зачёт», «экзамен»,
«математика», «проект», «отчёт», «договор», «поставка», «счёт». Каждая
координата вектора соответствует одному элементу словаря. При наличии слова
в~документе в~координату записывается его вес TF-IDF, при отсутствии слова "---
ноль.

При \( N = 5 \) слово «зачёт» встречается в~одном документе, и~его множитель
IDF равен \( \ln(5/(1+1)) \approx 0{,}916 \). В~первом документе это слово
встречается дважды, следовательно, соответствующая координата равна
\( 2 \cdot 0{,}916 = 1{,}832 \). Слово «математика» встречается в~двух
документах и~получает вес \( \ln(5/(2+1)) \approx 0{,}511 \). Слово «проект»
встречается в~трёх документах и~имеет вес
\( \ln(5/(3+1)) \approx 0{,}223 \). Векторы документов в~порядке признаков
словаря \( V \) имеют вид:
\[
    \begin{aligned}
        d_1 &= (1{,}832;\,0;\,0{,}511;\,0;\,0;\,0;\,0;\,0),\\
        d_2 &= (0;\,0{,}916;\,0{,}511;\,0{,}223;\,0;\,0;\,0;\,0),\\
        d_3 &= (0;\,0;\,0;\,0{,}446;\,0{,}916;\,0;\,0;\,0),\\
        d_4 &= (0;\,0;\,0;\,0{,}223;\,0;\,0{,}511;\,0{,}511;\,0),\\
        d_5 &= (0;\,0;\,0;\,0;\,0;\,0{,}511;\,0{,}511;\,0{,}916).
    \end{aligned}
\]
Такое представление переводит текстовые документы в~числовые объекты, для
которых применимы меры близости и~алгоритмы классификации.

Косинусная близость используется для сравнения двух векторов
документов:
\begin{equation}
    \label{eq:cosine}
    \cos(a,b) =
    \frac{\sum_{j=1}^{m} a_j b_j}
    {\sqrt{\sum_{j=1}^{m} a_j^2}\sqrt{\sum_{j=1}^{m} b_j^2}}.
\end{equation}
В~формуле \( a \) и~\( b \) обозначают векторы двух документов, \( a_j \)
и~\( b_j \) "--- значения \( j \)-го признака, \( m \) "--- число признаков.
Чем ближе значение \( \cos(a,b) \) к~единице, тем выше сходство документов
по~направлению их векторов. Значение, близкое к~нулю, соответствует малому
сходству в~пространстве признаков.

\textbf{Эмбеддинг текста} "--- это числовой вектор, предназначенный
для представления семантических свойств текста. В~отличие от~частотных
представлений, эмбеддинги позволяют учитывать близость документов при~различии
их лексического состава. Документы «оплата счёта» и~«платёж по~договору»
могут иметь близкие векторы, так как совпадение слов между ними минимально.

Документы «сдать лабораторную работу» и~«подготовить отчёт по предмету» должны
оказаться рядом, потому что оба связаны с~учёбой. Документ «оплатить счёт
за услуги» окажется дальше, потому что относится к~финансам. Такой способ
удобен для классификации и~для поиска групп похожих документов.

\section{Постановка задачи кластеризации}\label{sec:ch1/cluster}

Кластеризация "--- это разбиение объектов на~группы без заранее известных
меток. В~задаче с~документами она полезна, когда разметки ещё нет или её мало.
Алгоритм получает векторы документов и~пытается найти группы похожих текстов.

Формально после векторизации имеется набор объектов:
\[
    Z = \{z_i\}_{i=1}^{N}, \qquad z_i = \varphi(x_i) \in \mathbb{R}^{M}.
\]
Здесь \( x_i \) "--- текстовый документ, \( z_i \) "--- его числовой
вектор, \( N \) "--- число документов, а~\( M \) "--- число координат вектора.
Задача кластеризации состоит в~построении отображения
\[
    g: Z \rightarrow \{1, 2, \ldots, K\}.
\]
Значение \( g(z_i)=r \) означает, что документ \( i \) отнесён к~группе
\( r \).

Кластеры можно записать как множества
\[
    C_r = \{z_i \in Z \mid g(z_i)=r\}, \qquad r=1,\ldots,K.
\]

Для набора документов из~раздела~\ref{sec:ch1/repr} кластеризация должна
сблизить документы «зачёт зачёт математика» и~«экзамен математика проект»,
потому что оба текста относятся к~учебной тематике. Документы «договор поставка
проект» и~«договор поставка счёт» также должны оказаться рядом: в~них совпадают
слова о~договоре и~поставке. Документ «проект проект отчёт» может попасть
в~отдельную группу или стать пограничным объектом, потому что он связан
с~проектной тематикой, но~не~содержит явных учебных или финансовых признаков.

\textbf{K-Means} "--- простой метод кластеризации ~\autocite{MacQueen1967KMeans}.
Пользователь заранее задаёт число групп \( K \). Алгоритм выбирает центры
групп, относит каждый объект к~ближайшему центру, затем пересчитывает центры
и~повторяет эти действия.

Цель \( k \)-means можно записать так:
\begin{equation}
    \label{eq:kmeans}
    J = \sum_{i=1}^{N} \left\| z_i - c_{r_i} \right\|^2.
\end{equation}
Здесь \( J \) "--- суммарная ошибка разбиения, \( N \) "--- число документов,
\( z_i \) "--- вектор документа, \( c_{r_i} \) "--- центр группы,
к~которой отнесён документ \( i \), \( r_i \) "--- номер этой группы, а
\( \left\| z_i - c_{r_i} \right\|^2 \) "--- квадрат расстояния от~документа
до~центра его группы. Алгоритм старается сделать \( J \) как~можно меньше.

Допустим, есть шесть точек на~плоскости. Точки A, B и~C лежат
рядом с~координатой \((1;1)\), а~точки D, E и~F лежат рядом с~координатой
\((5;5)\). Если задать \( K=2 \), \( k \)-means найдёт два центра и~разделит
точки на~две группы.
Если же задать \( K=3 \), алгоритм всё равно создаст три группы, даже если
по~данным естественно видны только две. Это главный недостаток метода.

\textbf{DBSCAN} "--- плотностный метод кластеризации. Такие методы ищут
области, где точки стоят близко друг к~другу. Алгоритм
использует два параметра: радиус \( \varepsilon \) и~минимальное число соседей
\( m \)~\autocite{Ester1996DBSCAN}. Окрестность точки \( p \) задаётся так:
\begin{equation}
    \label{eq:eps-neighborhood}
    N_{\varepsilon}(p) = \{\,q \in Z \mid \operatorname{dist}(p,q) \leqslant \varepsilon\,\}.
\end{equation}
Здесь \( N_{\varepsilon}(p) \) "--- множество соседей точки \( p \),
\( Z \) "--- множество всех точек, \( q \) "--- другая точка из~этого множества,
\( \operatorname{dist}(p,q) \) "--- расстояние между точками \( p \) и~\( q \),
а~\( \varepsilon \) "--- максимальное расстояние, при~котором точки считаются
соседями.

Если у~точки достаточно соседей внутри радиуса \( \varepsilon \), она становится
ядром группы. От~таких точек группа расширяется на~соседей. Точки, которые
не~попали ни~в~одну плотную область, остаются вне групп. Например, рассмотрим
четыре двумерные точки: \(p_1=(0;0)\), \(p_2=(0{,}1;0)\),
\(p_3=(0;0{,}1)\) и~\(p_4=(3;3)\). При~\(\varepsilon=0{,}2\) и~\(m=3\)
первые три точки попадают в~одну плотную область, потому что находятся близко
друг к~другу, а~точка \(p_4\) остаётся отдельной и~может быть оставлена вне
групп.

\textbf{HDBSCAN} развивает эту идею и~не~требует одного общего радиуса для всех групп
\autocite{McInnes2017HDBSCAN}. Метод смотрит на~данные при
разных уровнях плотности и~оставляет устойчивые группы. Для сравнения точек
используется расстояние взаимной достижимости:
\begin{equation}
    \label{eq:mreach}
    d_{\mathrm{mreach}}(a,b) =
    \max\{\,\mathrm{core}_m(a),\ \mathrm{core}_m(b),\ d(a,b)\,\}.
\end{equation}
Здесь \( d_{\mathrm{mreach}}(a,b) \) "--- расстояние взаимной достижимости
между точками \( a \) и~\( b \), \( \mathrm{core}_m(a) \) "--- расстояние
от~точки \( a \) до~её \( m \)-го ближайшего соседа, \( \mathrm{core}_m(b) \)
"--- такое~же расстояние для точки \( b \), \( d(a,b) \) "--- обычное расстояние
между \( a \) и~\( b \), а~\( \max \) выбирает наибольшее из~трёх значений.

На~простых данных это можно понять так. В~плотной группе ближайшие соседи
находятся совсем рядом, поэтому расстояние взаимной достижимости почти совпадает
с~обычным расстоянием. У~одинокой точки ближайшие соседи далеко, поэтому её
расстояние до~других точек становится большим. Такая точка остаётся вне групп
и~не~входит ни~в~один кластер. Благодаря этому HDBSCAN легче отделяет
устойчивые группы от~одиночных объектов.

\section{Уменьшение размерности эмбеддингов}\label{sec:ch1/umap}

Эмбеддинг документа обычно имеет сотни или тысячи координат. Такая размерность
появляется потому, что трансформер хранит результат обработки текста в~скрытом
пространстве модели: каждая координата участвует в~описании смысла, контекста и
лексических признаков, но~редко соответствует одному понятному человеку
свойству. В~таком пространстве данные нельзя напрямую показать на~рисунке,
а~поиск групп становится менее устойчивым: лишние и~случайные координаты могут
искажать расстояния между документами.

Снижение размерности переводит эмбеддинги в~меньшее число координат. Для
визуализации обычно выбирают две или три координаты, чтобы построить рисунок.
Для кластеризации часто оставляют больше координат, чем для рисунка, но~меньше,
чем в~исходном эмбеддинге. Это помогает убрать часть случайных отличий
и~избыточных направлений, сохранить главную структуру соседства и~сделать
расстояния между документами более полезными для методов K-Means, DBSCAN
и~HDBSCAN.
Без такого шага алгоритм может группировать документы по~случайным отличиям
в~сотнях координат, а~не~по~устойчивым тематическим признакам.

\section{Метрики качества}\label{sec:ch1/metrics}

Качество системы оценивается отдельно для классификации и~кластеризации.
Классификатор сравнивается с~правильными метками проверочного набора.
Кластеризация не~имеет заранее заданных правильных меток, поэтому для неё
используются внутренние показатели компактности и~разделимости групп.

\subsection{Метрики качества классификатора}\label{subsec:ch1/task/metrics}

Для проверки классификатора используется набор
\( D_{\mathrm{test}} = \{(x_i,y_i)\}_{i=1}^{N_{\mathrm{test}}} \), где
\( x_i \) "--- документ, а~\( y_i \in Y \) "--- его правильная категория. Ответ
классификатора обозначается через \( \hat{y}_i = a_{\tau}(x_i) \). При наличии
правила с~отказом значение \( \hat{y}_i \) может быть равно \( \bot \), как
в~формуле~\eqref{eq:decision-rule}.

Для класса \( c_k \) вводятся три счётчика. Величина \( t_k \) обозначает число
документов, для которых одновременно выполнены условия \( y_i=c_k \) и
\( \hat{y}_i=c_k \). Величина \( \hat{n}_k \) обозначает число документов,
отнесённых классификатором к~классу \( c_k \). Величина \( n_k \) обозначает
число документов, которые действительно относятся к~классу \( c_k \).

Точность \( P_k \) показывает, какая доля документов, отнесённых классификатором
к~классу \( c_k \), действительно принадлежит этому классу
\autocite{Sokolova2009Metrics,Manning2008IR}:
\begin{equation}
    \label{eq:precision}
    P_k = \frac{t_k}{\hat{n}_k}.
\end{equation}
Чем меньше среди назначений класса \( c_k \) ошибочных документов, тем больше
значение \( P_k \).

Полнота \( R_k \) показывает, какая доля документов класса \( c_k \) была найдена
классификатором:
\begin{equation}
    \label{eq:recall}
    R_k = \frac{t_k}{n_k}.
\end{equation}
Если классификатор отказался от~автоматического решения для документа класса
\( c_k \), такой документ входит в~\( n_k \), но~не~входит в~\( t_k \).

F1-мера \( F_{1,k} \) объединяет точность и~полноту для класса \( c_k \):
\begin{equation}
    \label{eq:f1}
    F_{1,k} =
    \frac{2 P_k R_k}{P_k + R_k}.
\end{equation}
Если один из~показателей \( P_k \) или \( R_k \) мал, то значение \( F_{1,k} \)
также снижается. Поэтому F1-мера учитывает как ошибочные назначения класса, так
и~пропуски документов этого класса.

Для многоклассовой задачи используется средняя F1-мера по~классам:
\begin{equation}
    \label{eq:macro-f1}
    \overline{F}_1 =
    \frac{1}{K}\sum_{k=1}^{K} F_{1,k}.
\end{equation}
В~формуле \( \overline{F}_1 \) обозначает среднюю F1-меру, \( K \) "--- число
пользовательских категорий, а~\( F_{1,k} \) "--- значение F1-меры для класса
\( c_k \). Такое усреднение даёт каждому классу одинаковый вес.

Доля верных ответов \( A \) показывает, какая часть проверочного набора получила
правильную метку:
\begin{equation}
    \label{eq:accuracy}
    A =
    \frac{1}{N_{\mathrm{test}}}\sum_{i=1}^{N_{\mathrm{test}}}
    \mathbb{1}\bigl[\,\hat{y}_i = y_i\,\bigr].
\end{equation}
Здесь \( \mathbb{1}[\cdot] \) равно единице при~истинном условии и~нулю
при~ложном. Если \( \hat{y}_i=\bot \), то документ не~считается верно
классифицированным.

Для правила с~отказом дополнительно вычисляется покрытие \( C_{\tau} \). Оно
показывает долю документов, для которых классификатор выдал одну из~категорий
множества \( Y \):
\begin{equation}
    \label{eq:coverage}
    C_{\tau} =
    \frac{1}{N_{\mathrm{test}}}\sum_{i=1}^{N_{\mathrm{test}}}
    \mathbb{1}\bigl[\,\hat{y}_i \neq \bot\,\bigr].
\end{equation}
Покрытие рассматривается вместе с~F1-мерой. При большом покрытии и~низкой
F1-мере система принимает много ненадёжных решений; при малом покрытии она
часто передаёт документы на~ручную разметку.

\subsection{Метрики качества кластеризации}\label{subsec:ch1/cluster/metrics}

Кластеризация оценивается иначе, чем классификация, потому что правильные метки
групп обычно заранее неизвестны. Поэтому используются внутренние метрики,
которые вычисляются по~расстояниям между объектами и~по~структуре найденных
кластеров.

Коэффициент силуэта \( s_i \) оценивает положение объекта \( z_i \) относительно
собственной и~соседних групп~\autocite{Rousseeuw1987Silhouette}. Пусть
\( a_i \) обозначает среднее расстояние от~объекта \( z_i \) до~объектов своего
кластера, а~\( b_i \) "--- наименьшее среднее расстояние от~\( z_i \) до
объектов другого кластера. Тогда:
\begin{equation}
    \label{eq:silhouette}
    s_i = \frac{b_i - a_i}{\max(a_i,b_i)}.
\end{equation}
Значение \( s_i \), близкое к~единице, означает, что объект ближе к~своему
кластеру, чем к~соседним. Значение около нуля указывает на~пограничное
положение объекта.

Индекс Дэвиса"--~Боулдина сравнивает внутрикластерный разброс и~расстояние между
группами~\autocite{Davies1979DBI}. Пусть \( C_r \) "--- \( r \)-я группа,
\( c_r \) "--- её центр, \( K \) "--- число групп, а~\( d(\cdot,\cdot) \) "---
выбранная метрика расстояния. Сначала для каждой группы вычисляется среднее
отклонение объектов от~центра:
\begin{equation}
    \label{eq:davies-bouldin-scatter}
    S_r = \frac{1}{|C_r|}\sum_{z_i\in C_r} d(z_i,c_r).
\end{equation}
Величина \( S_r \) характеризует компактность группы \( C_r \): чем она меньше,
тем ближе объекты расположены к~центру группы.

Для пары групп \( C_r \) и~\( C_s \) расстояние между центрами задаётся как
\begin{equation}
    \label{eq:davies-bouldin-distance}
    M_{rs} = d(c_r,c_s).
\end{equation}
Большое значение \( M_{rs} \) означает, что центры двух групп хорошо разделены
в~выбранном пространстве признаков.

Затем для пары групп вычисляется отношение
\begin{equation}
    \label{eq:davies-bouldin-ratio}
    R_{rs} = \frac{S_r + S_s}{M_{rs}}.
\end{equation}
Это отношение возрастает, если группы имеют большой внутренний разброс или их
центры расположены близко друг к~другу.

Итоговый индекс Дэвиса"--~Боулдина равен среднему худших отношений для всех
групп:
\begin{equation}
    \label{eq:davies-bouldin}
    \operatorname{DBI} =
    \frac{1}{K}\sum_{r=1}^{K}\max_{s\ne r} R_{rs}.
\end{equation}
Меньшее значение DBI соответствует более компактным и~лучше разделённым
группам. Индекс удобен для сравнения разбиений без правильных меток, но~хуже
описывает вытянутые или сложные по~форме кластеры, так как опирается на~центры
групп.

Для плотностных методов применяется DBCV (Density-Based Clustering Validation).
Эта метрика оценивает плотностную связность групп и~поэтому подходит для DBSCAN
и~HDBSCAN~\autocite{Moulavi2014DBCV}. Пусть \( d_{\mathrm{mreach}} \) "---
расстояние взаимной достижимости из~формулы~\eqref{eq:mreach}. Для группы
\( C_r \) строится минимальное остовное дерево по~этим расстояниям, после чего
вычисляется внутренняя разреженность:
\begin{equation}
    \label{eq:dbcv-dsc}
    \mathrm{DSC}_r = \max_{e\in\mathrm{MST}(C_r)} w(e).
\end{equation}
Здесь \( w(e) \) обозначает вес ребра \( e \). Величина \( \mathrm{DSC}_r \)
растёт, если внутри группы есть слабая плотностная связь или длинный переход
между частями группы.

Отделение группы от~других групп задаётся величиной
\begin{equation}
    \label{eq:dbcv-dspc}
    \mathrm{DSPC}_r =
    \min_{s\ne r}\min_{\substack{z_i\in C_r\\ z_j\in C_s}}
    d_{\mathrm{mreach}}(z_i,z_j).
\end{equation}
Величина \( \mathrm{DSPC}_r \) показывает ближайшее плотностное расстояние от
группы \( C_r \) до~любой другой группы.

Для одной группы качество плотностного отделения записывается как
\begin{equation}
    \label{eq:dbcv-cluster-score}
    V_r =
    \frac{\mathrm{DSPC}_r-\mathrm{DSC}_r}
    {\max(\mathrm{DSPC}_r,\mathrm{DSC}_r)}.
\end{equation}
Значение \( V_r \) положительно, если отделение от~соседних групп больше
внутренней разреженности, и~отрицательно, если группа плохо отделена или внутри
неё есть слабая плотностная связь.

Итоговая метрика DBCV усредняет значения \( V_r \) с~учётом размеров групп:
\begin{equation}
    \label{eq:dbcv}
    \operatorname{DBCV} =
    \sum_{r=1}^{K}\frac{|C_r|}{n}V_r.
\end{equation}
Здесь \( n \) обозначает число объектов, вошедших в~группы. Значение DBCV лежит
в~диапазоне от~\(-1\) до~\(1\); чем оно больше, тем лучше плотностная структура
кластеризации.

Дополнительно учитываются число найденных групп, размеры групп и~доля объектов,
оставленных вне групп. Эти показатели не~заменяют содержательную проверку, но
помогают понять, насколько полученное разбиение пригодно для последующей
разметки документов.

\section{Постановка задачи разработки}\label{sec:ch1/dev}

На~основе рассмотренных подходов задача разработки сводится к~созданию локальной
системы, которая принимает текстовые документы, подготавливает их, строит
числовые представления, помогает получить категории и~классифицирует новые
документы с~оценкой уверенности.

Для решения поставленной задачи процесс должен давать проверяемый результат
после каждого этапа.

\begin{enumerate}
    \item Подготовить текстовые документы к~обработке. Ожидаемый результат:
        каждый документ представлен очищенным текстом в~едином виде. Например,
        строка «ОТЧЁТ!!! По проекту. Версия 2. С уважением, Иван» после
        нормализации может превратиться в~«отчёт проект версия».
    \item Построить числовые представления документов. Ожидаемый результат:
        каждый документ представлен вектором признаков или эмбеддингом.
    \item Найти группы похожих документов, если готовой разметки нет или её мало.
        Ожидаемый результат: документы разделены на~группы похожих текстов, а
        плохо подходящие к~устойчивым группам документы оставлены вне групп.
    \item Подготовить размеченное множество. Ожидаемый результат: полученные
        категории можно использовать для разметки множества документов
        и для построения классификатора.
    \item Построить классификатор на~размеченных данных. Ожидаемый результат:
        для нового документа можно получить оценку принадлежности к~каждой
        известной категории.
    \item Настроить решающее правило с~порогом уверенности. Ожидаемый результат:
        документ получает категорию только тогда, когда максимальная оценка
        достаточно велика. Если оценка ниже порога, алгоритм возвращает отказ,
        а~не~назначает слабую категорию.
    \item Оценить качество работы. Ожидаемый результат: рассчитаны метрики
        классификации и~кластеризации.
\end{enumerate}

\section{Критерии успешного решения задачи}\label{sec:ch1/success}\label{subsec:ch1/dev/success}

Задача считается решённой, если выполняются следующие условия.

\begin{enumerate}
    \item Документы обрабатываются локально, без~передачи полного текста
        во~внешние сервисы.
    \item Документы проходят предобработку и~получают числовые представления,
        по~которым можно сравнивать похожие тексты.
    \item Если разметки недостаточно, похожие документы можно сгруппировать и
        использовать эти группы как основу для назначения категорий человеком.
    \item Классификатор выдаёт категорию и~оценку уверенности, а~при~низкой
        уверенности возвращает отказ от~автоматического решения.
    \item Качество классификации оценивается по~доле верных ответов, средней
        F1-мере и~покрытию,
        а~качество группировки "--- по~внутренним метрикам кластеризации
        и~содержательной проверке полученных групп.
\end{enumerate}
