## Ключевые решения (согласовано с автором)

1. **Роль главы.** «Реализация и экспериментальное исследование системы»:
   реализация (с листингами) + эксперименты. Не «только эксперименты» и не
   «только реализация».
2. **Листинги.** Компактные фрагменты ключевого кода (≈10–40 строк) — в тексте
   главы с разбором; полные/длинные модули — в приложение через
   `\lstinputlisting`. Пакет `listings` уже настроен (`Dissertation/userpackages.tex`,
   стиль и подпись «Листинг» в `Dissertation/userstyles.tex`); пример
   `\lstinputlisting` уже есть в `Dissertation/appendix.tex`.
3. **Данные.** Реальный почтовый ящик автора (ru+en), синхронизированный по IMAP.
   В тексте — обезличенное описание (объём выборки, доли языков, период,
   результаты фильтра качества), без приватного содержимого; примеры писем
   анонимизированы.
4. **Блоки результатов (выбраны автором, уточнены по итогам ревью):**
   - (1) Кластеризация: метрики (число кластеров, доля шума, DBCV, силуэт,
     индекс Дэвиса–Боулдина) + 2D-проекция + таблица топ-терминов TF-IDF.
   - (2) Подбор параметров (Optuna): история оптимизации, лучшие параметры,
     важность + сравнение HDBSCAN+тюнер vs дефолтные параметры vs KMeans.
   - (3) Классификатор: accuracy, macro-F1, weighted-F1, покрытие, доля `other`,
     поклассовые precision/recall/F1 (с support), матрица ошибок, развёртка
     метрик по порогу уверенности τ.
   - (4) **Цикл переобучения (минимальный сценарий):** демонстрация
     `other → ручная проверка → переобучение → активация новой версии` —
     ради честного закрытия критерия успеха №4 (`subsec:ch1/dev/success`).
     Не полноценное исследование дрейфа, а компактный сценарий с фиксацией
     версий модели.
   - **Не включаем:** качественный анализ отдельных примеров; производительность
     и латентность (см. решение 10).
5. **Структура — по этапам конвейера (вариант B).** Для каждого этапа
   реализация (листинг) и его результат идут вместе. Слабость варианта —
   «размазанная» оценка качества — компенсируется финальным сводным разделом
   «достигнуто против критериев успеха» (`subsec:ch1/dev/success`).
6. **Оценочный слой в `diplom2.0` (рабочая линия A).** Текущий код не выдаёт
   часть требуемых артефактов; они добавляются как часть работы над главой
   (см. раздел «Изменения в коде `diplom2.0`»). Глава становится воспроизводимой.
7. **Плейсхолдеры — заметный grep-абельный макрос.** `\fixme` в проекте
   определён как `\textcolor{black}` (`common/styles.tex`), то есть **не** красный
   и легко теряется. Для черновых плейсхолдеров главы 3 вводится локальный
   заметный макрос (красный жирный, например `\ph{...}` → `⟨...⟩`), легко
   ищется по `\ph{` и удаляется при подстановке реальных значений. `\fixme`
   используется только там, где он уже стоит в шаблоне.
8. **Протокол оценки классификатора — gold-тест, grouped по кластеру.**
   Тестовая выборка — только человеко-проверенные метки (прямая разметка
   представителей), сплит сгруппирован по кластеру (письма одного кластера не
   попадают в train и test одновременно — исключает утечку от распространения
   меток), фиксированный seed, отчёт по support на класс. Текущий случайный
   `_split_train_validation` (`training/train.py`) для финальной оценки
   не используется.
9. **Протокол сравнения с KMeans.** k выбирается равным числу кластеров HDBSCAN
   после тюнинга (для сопоставимости; при необходимости — по максимуму силуэта
   на сетке k, способ указывается). Внутренние метрики (силуэт, индекс
   Дэвиса–Боулдина) для честного сравнения считаются на не-шумовых точках для
   обоих алгоритмов (KMeans шума не порождает). DBCV приводится для HDBSCAN;
   для KMeans он неинформативен и не сравнивается. Доля покрытых точек
   (1 − доля шума) приводится как контекст.
10. **Критерий латентности (CPU) удалён.** По решению автора критерий успеха №2
    (среднее время инференса на CPU) исключается из работы. Требуется
    **минимальная правка** `subsec:ch1/dev/success` в `Dissertation/part1.tex`:
    удалить пункт про латентность на CPU. Сводная таблица главы 3 закрывает
    критерии 1, 3 и 4; латентность не измеряется и не заявляется.

модулей→назначение либо ссылка на таблицу главы 2 (без дублирования архитектуры).

**3.2 Данные, экспериментальная установка и протокол оценки**
(`\label{sec:ch3/setup}`)
Обезличенное описание корпуса: объём, доли ru/en, период, результаты фильтра
качества (`ok/empty/too_short`). Аппаратная конфигурация и версии (модель

### Стержень — этапы конвейера (реализация + результат)

**3.3 Синхронизация и нормализация** (`\label{sec:ch3/norm}`)
Листинг Л3.2 — нормализация. Токенизация `LINK/EMAIL/DATE/TIME/NUM` живёт в
`data/preprocessing.py:normalize_text`; `email/normalization.py:normalize_raw_email`
**делегирует** ей и добавляет срез цитат/подписей/футеров (ru/en),
определение языка и оценку качества. Листинг показывает оба фрагмента (либо
описывает делегирование явно). Результат: таблица распределения качества и
языков (Т3.2) + анонимизированный пример «до/после» нормализации.

**3.4 Построение эмбеддингов** (`\label{sec:ch3/embed}`)
Листинг Л3.3 (`clustering/embeddings.py`): батчевое построение, кеш `.npz`,
индексная запись в `email_embeddings`. Результат: размерность векторов, число
векторов после фильтра, размер кеша, время построения (плейсхолдеры).

**3.5 Кластеризация и подбор параметров** (`\label{sec:ch3/cluster}`) — блоки
результатов 1 и 2.
Листинг Л3.4 (`clustering/tuner.py`): целевая функция Optuna (DBCV + добавки за
устойчивость кластеров и уверенность принадлежности − штраф за долю шума, при
ограничениях допустимости). Результаты:
- Подбор параметров: рисунок F3.2 (история оптимизации Optuna), таблица Т3.6
  (лучшие `min_cluster_size`/`min_samples`, значение цели, важность параметров).
  Источник — Optuna-артефакт, сохраняемый расширенным `tuner.py` (рабочая линия A).
- Сравнение (решение 9): таблица Т3.3 (HDBSCAN+тюнер vs дефолтные параметры vs
  KMeans; силуэт и индекс Дэвиса–Боулдина на не-шумовых точках, DBCV — для
  HDBSCAN, доля покрытия — контекст).
- Итоговый запуск: таблица Т3.4 (число кластеров, доля шума, DBCV, силуэт,
  индекс Дэвиса–Боулдина — сохраняются расширенным `pipeline.py`), рисунок F3.1
  (2D-проекция кластеров, UMAP, из `clustering/visualization.py`), таблица Т3.5
  (топ-термины TF-IDF по кластерам из `clustering/summaries.py`).

**3.6 Ручная проверка и формирование классов** (`\label{sec:ch3/annot}`)
Листинг Л3.5 (`annotation/import_labels.py`): распространение согласованной метки
на кластер и strict-режим (разногласие представителей → `other`). Результат:
кластеры → классы после консолидации, объём ручного труда (число представителей
vs всего писем), таблица итоговых классов и их размеров (Т3.7).

**3.7 Классификатор: обучение и оценка** (`\label{sec:ch3/clf}`) — блок 3,
часть 1.
Листинг Л3.6 (`models/text_classifier.py`): собственный словарь + обучаемые
эмбеддинги, mean-pooling, линейная голова (контракт `oid,text,label`).
Результат на gold-тесте (решение 8): accuracy, macro-F1, weighted-F1, покрытие;
поклассовые precision/recall/F1 с support (таблица Т3.8); матрица ошибок
(рисунок F3.3). Метрики порождает расширенный `evaluation/metrics.py` (линия A);
обучение — `training/train.py`, `training/text_vectorizer.py`.

**3.8 Инференс и порог уверенности τ** (`\label{sec:ch3/infer}`) — блок 3,
часть 2.
Листинг Л3.7 (`inference/predict.py`): решающее правило — softmax-вероятности,
confidence (max prob), перевод низкоуверенных (по порогу τ) в `other`. Текущий
`predict()` возвращает только argmax; вероятностный путь добавляется (линия A).
Результат: развёртка метрик по τ (покрытие vs точность/macro-F1; доля `other`) —
рисунок F3.4 и/или таблица Т3.9, выбор рабочего τ.

**3.9 Демонстрация цикла переобучения** (`\label{sec:ch3/loop}`) — блок 4
(критерий успеха №4).
Компактный сценарий `other → ручная проверка → переобучение → активация новой
версии`: накопление буфера `other` до порога N, перекластеризация буфера,
разметка, обучение новой версии, активация по quality gates. Фиксируются версии
модели до/после (`model_versions`) и факт активации. Не исследование дрейфа, а
подтверждение работоспособности цикла.

## Изменения в коде `diplom2.0` (рабочая линия A — оценочный слой)

Текущий код не выдаёт часть требуемых артефактов (подтверждено ревью). Нужные
изменения (порождают данные для таблиц/рисунков; латентность не реализуется —
решение 10):

1. **Инференс с вероятностями** — `inference/predict.py`: метод, возвращающий
   softmax-вероятности и confidence (max prob) помимо argmax; решающее правило с
   порогом τ → `other` для низкоуверенных. Сейчас `predict()` отдаёт только
   argmax (`list[str]`).
2. **Метрики классификации** — `evaluation/metrics.py`: добавить покрытие
   (доля не-`other`), долю `other`, поклассовые precision/recall/F1 с support,
   матрицу ошибок; функцию развёртки метрик по сетке τ. Сейчас считаются только
   accuracy/macro-F1/weighted-F1.
3. **Метрики кластеризации** — `clustering/pipeline.py`: сохранять в
   `cluster_runs.metrics` DBCV, силуэт, индекс Дэвиса–Боулдина (силуэт/DBI — на
   не-шумовых точках). Сейчас сохраняются только счётчики
   кластеров/выбросов/долей.
4. **Optuna-артефакты** — `clustering/tuner.py`: сохранять study (история
   значений, лучшие параметры, важность параметров) в файл-артефакт (JSON/CSV)
   для F3.2 и Т3.6. Сейчас возвращаются только параметры (DBCV/noise — в
   `trial.user_attrs`/логах, не персистятся).
5. **Протокол оценки** — утилита grouped-by-cluster split (gold-тест из
   человеко-проверенных меток), фикс seed (решение 8). Не использовать случайный
   `_split_train_validation` для финальной оценки.
