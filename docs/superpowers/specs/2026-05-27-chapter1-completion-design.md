## 2. Структура секций

### 2.1. §1.3 «Методы представления текста для классификации»

**Объём:** ~3 страницы.

**Цель:** изложить семейства векторизаторов \( \varphi \colon X \to \mathbb{R}^d \),
рассматриваемых как кандидаты для постановки §1.2; зафиксировать, какие из них в
принципе работоспособны для multilingual + locality.

**Подразделы (3 содержательных + 1 связующий абзац):**

1. **Счётные представления.** Bag-of-Words и TF-IDF
   \autocite{Manning2008IR, Salton1988TFIDF}: интерпретируемые признаки,
   ограниченность семантической близости, плохая переносимость между языками.
2. **Статичные дистрибутивные эмбеддинги.** word2vec
   \autocite{Mikolov2013word2vec}, GloVe \autocite{Pennington2014GloVe},
   fastText \autocite{Bojanowski2017fastText} (subword покрывает OOV); кратко —
   RusVectores \autocite{Kutuzov2017RusVectores} как русскоязычный
   эталонный набор.
3. **Контекстные и multilingual представления.** BERT
   \autocite{Devlin2019BERT}, XLM-R \autocite{Conneau2020XLMR},
   Sentence-BERT \autocite{Reimers2019SBERT}, multilingual SBERT
   \autocite{Reimers2020MultilingualSBERT}, LaBSE \autocite{Feng2022LaBSE}.
4. **Сводная типология и связка.** TikZ-схема, показывающая прогрессию
   «счётные → статичные → контекстные → multilingual» с примерами моделей.
   Завершается одним абзацем-связкой: только последняя группа методов
   одновременно покрывает свойство multilingual без переобучения с нуля;
   вопросы локального исполнения и латентности оставляются для главы 2.

**Иллюстрация:** `Dissertation/images/embedding_taxonomy.tikz` (новый файл).
Стиль и `\input{...}` — по образцу существующего `classification_scheme.tikz`.

**Метка рисунка:** `fig:embedding-taxonomy`.

### 2.2. §1.4 «Методы классификации текстов»

**Объём:** ~3 страницы.

**Цель:** перечислить семейства классификаторов \( f_\theta \), отметив
совместимость с (а) ограниченной размеченной выборкой, (б) инкрементным
обучением (нужно для concept drift из §1.2.4), (в) калиброванной
вероятностью \( p_k(x) \) (нужно для правила (1.4)).

**Подразделы (4 содержательных + связка):**

1. **Вероятностные и линейные методы.** Naive Bayes
   \autocite{McCallum1998NaiveBayes}, логистическая регрессия и линейные SVM
   поверх TF-IDF \autocite{Joachims1998SVMTextCat}; быстрые реализации —
   LIBLINEAR \autocite{Fan2008LIBLINEAR}, scikit-learn
   \autocite{Pedregosa2011sklearn}.
2. **Онлайн-классификаторы.** Passive-Aggressive
   \autocite{Crammer2006PA}, Confidence-Weighted Linear Classification
   \autocite{Dredze2008CW} (упоминаются в TaskTracer
   \autocite{Keiser2009TaskTracer}) как естественная реакция на дрейф.
3. **Деревья и бустинг.** Random Forest \autocite{Breiman2001RF},
   XGBoost \autocite{Chen2016XGBoost}, LightGBM \autocite{Ke2017LightGBM}:
   хорошо работают на табличных признаках, ограничены при больших разреженных
   текстовых векторах.
4. **Нейронные классификаторы поверх эмбеддингов.** Линейная / MLP-голова
   поверх SBERT-векторов; fine-tuning энкодера; калибровка вероятностей —
   Platt-scaling, temperature scaling \autocite{Guo2017Calibration}; базовая
   OOD-эвристика «max softmax» \autocite{Hendrycks2017Baseline} как минимально
   необходимая инфраструктура для содержательного использования категории
   `other` по правилу (1.4).

Завершающая фраза-связка: для постановки §1.2 нужны калиброванная
уверенность и поддержка инкрементного обновления; конкретный выбор
архитектуры — глава 2.

### 2.3. §1.5 «Методы кластеризации для bootstrap классов»

**Объём:** ~3 страницы.

**Цель:** изложить методы получения первичных классов из неразмеченного
архива, с акцентом на явное выделение шумовых сообщений (естественный
прообраз категории `other`).

**Подразделы (3 + связка):**

1. **Партиционные методы.** k-means / k-means++
   \autocite{MacQueen1967KMeans, Arthur2007KMeansPP}: требуют заданного
   числа кластеров, не выделяют выбросы, чувствительны к выбору метрики.
2. **Плотностные методы.** DBSCAN \autocite{Ester1996DBSCAN}, HDBSCAN
   \autocite{Campello2013HDBSCAN, McInnes2017HDBSCAN}: переменное число
   кластеров, явная категория шума — структурно соответствует `other`.
3. **Снижение размерности и альтернативы.** UMAP
   \autocite{McInnes2018UMAP} как способ работать с высокоразмерными
   эмбеддингами; тематические модели LDA \autocite{Blei2003LDA} как
   смежная альтернатива на интерпретируемых признаках.

Дополнительно — краткое замечание о метриках качества кластеризации
(силуэт \autocite{Rousseeuw1987Silhouette}, Davies-Bouldin
\autocite{Davies1979DBI}) и о расхождении численного оптимума с
пригодностью кластеров для ручной аннотации.

**Иллюстрация:** `Dissertation/images/clustering_outliers.tikz` — две панели
«k-means (все точки покрашены)» против «HDBSCAN (часть точек — шум)» на
синтетических данных. Стиль — по образцу `classification_scheme.tikz`.

**Метка рисунка:** `fig:clustering-outliers`.

### 2.4. §1.6 «Сравнительный анализ существующих систем»

**Объём:** ~4–5 страниц (с таблицей).

**Цель:** показать, что ни одна из существующих систем не покрывает
одновременно четыре свойства задачи из §1.1 и формальную постановку §1.2.

**Структура:**

- Вступление: какие системы рассматриваются, по каким осям сравнения; оси
  повторяют свойства из §1.1 и (1.4).
- Разборы (по 0.5–1 странице каждый):
  1. **Outlook Focused Inbox** \autocite{Microsoft2024FocusedInbox} —
     бинарная шкала, серверное обучение.
  2. **Gmail Priority Inbox** \autocite{Aberdeen2010PriorityInbox} —
     персонализированная логистическая модель, importance-бинарная,
     серверная обработка.
  3. **TaskTracer** \autocite{Keiser2009TaskTracer} — персонализация по
     проектам, онлайн-классификаторы; нет `other`-категории, нет multilingual.
  4. **EmFORE** \autocite{Singh2023EmFORE} — индуктивные правила, явный
     drift, опирается на структурные признаки; кластеризация не используется.
- Однострочное упоминание ручных фильтров почтового клиента и пользовательских
  правил Sieve со ссылкой на §1.1.
- **Таблица 1.1.** Колонки: персонализированные классы / multilingual /
  locality / явный `other` / concept drift / источник классов / обратная
  связь. Строки: 4 системы + «настоящая работа (целевые требования)».
  Метка: `tab:systems-compare`.
- Вывод: ни одна строка (кроме целевой) не закрывает все колонки — это и
  есть пробел, который закрывает работа.

**Источники:** все четыре уже присутствуют в `biblio/external.bib`.
